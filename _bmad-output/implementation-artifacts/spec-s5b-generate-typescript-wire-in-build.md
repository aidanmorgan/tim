## Intent

**Problem:** The first 12,731 lines of `tools/e2e/workshop-wire.ts` are FlatBuffers-compiler TypeScript, regenerated by hand by the procedure at `schemas/README.md:55-75` (since S5, with S5's cached pinned compiler) and committed. Between `66da1ae7` (4 November 2026) and `25df3cd5` 16 commits touched it (`git log --oneline 66da1ae7..25df3cd5 -- tools/e2e/workshop-wire.ts | wc -l`) and the two revisions differ by +5,884/−2,068 lines (`git diff --shortstat 66da1ae7 25df3cd5 -- tools/e2e/workshop-wire.ts`), every line of which went through review, and nothing compares it with the schemas, so a schema edit with stale TypeScript is caught only by a deferred browser run.

The TypeScript FlatBuffers runtime the generated code imports is unpinned: `tools/e2e/tsconfig.json:16` maps `flatbuffers` to `/opt/homebrew/lib/node_modules/flatbuffers`, which is in neither `package.json` nor `package-lock.json` (ABI audit G12, `docs/planning/elements/readiness/audits/abi-interfaces.md`).

**Approach:** After S5, the vendored project `CuriousContraptions.FlatBuffers` also runs the same digest-verified pinned compiler once per build with `--ts` in one invocation over every schema, ordered so that every schema another schema includes comes first and the last is one that no schema includes (today `schemas/workshop_authoring.fbs`, which includes the wire schema); the last schema's run writes the one entry module, which then re-exports every type it reaches, into one ignored directory, and applies the README's annotation normalisation there. The generated part leaves the repository; `workshop-wire.ts` keeps only the hand-written helpers and imports generated names from the generated entry module, and every consumer imports generated names from where they are generated. The npm `flatbuffers` runtime is pinned at exactly 25.2.10, the compiler's version, as a devDependency of a `tools/e2e`-local `package.json` with its `package-lock.json`, installed only when the browser phase runs (coordinator decision of 25 November 2026, BH2), and the Homebrew `paths` mapping is removed, so the generated code and its runtime come from one pinned version (owner decision 24j: wire code is generated from schemas, never hand-coded).
