## Intent

**Problem:** The first 12,731 lines of `tools/e2e/workshop-wire.ts` are FlatBuffers-compiler TypeScript, regenerated by hand from `schemas/README.md:41-62` with whatever `flatc` is on `PATH` and committed. Between `66da1ae7` (4 November 2026) and `25df3cd5` 16 commits touched it (`git log --oneline 66da1ae7..25df3cd5 -- tools/e2e/workshop-wire.ts | wc -l`) and the two revisions differ by +5,884/−2,068 lines (`git diff --shortstat 66da1ae7 25df3cd5 -- tools/e2e/workshop-wire.ts`), every line of which went through review, and nothing compares it with the schemas, so a schema edit with stale TypeScript is caught only by a deferred browser run.

The TypeScript FlatBuffers runtime the generated code imports is unpinned: `tools/e2e/tsconfig.json:16` maps `flatbuffers` to `/opt/homebrew/lib/node_modules/flatbuffers`, which is in neither `package.json` nor `package-lock.json` (ABI audit G12, `docs/planning/elements/readiness/audits/abi-interfaces.md`).

**Approach:** After S5, the vendored project `CuriousContraptions.FlatBuffers` also runs the same digest-verified pinned compiler once per build with `--ts --gen-all` on `schemas/workshop_authoring.fbs` (which includes the wire schema, so one run writes every type and one entry module that re-exports them), into one ignored directory, and applies the README's annotation normalisation there. The generated part leaves the repository; `workshop-wire.ts` keeps only the hand-written helpers and imports generated names from the generated entry module, and every consumer imports generated names from where they are generated. The npm `flatbuffers` runtime is pinned at exactly 25.2.10, the compiler's version, as a devDependency of the root `package.json` with its `package-lock.json` entry, and the Homebrew `paths` mapping is removed, so the generated code and its runtime come from one pinned version (owner decision 24j: wire code is generated from schemas, never hand-coded).

## Boundaries & Constraints

**Always:**
- The compiler is S5's cached, digest-verified 25.2.10 binary, obtained by S5's provisioning target; the C# and TypeScript steps live in the one vendored project file and declare the same inputs (both schemas, the project file, the pinned digest), so neither can be stale while the other is fresh.
- Generated TypeScript is written only under `tools/e2e/.wire/`, which is listed in `.gitignore`, cleared before each generation and registered as `FileWrites`; no generated TypeScript is tracked.
- One writer per build graph: the TypeScript step runs in exactly one project invocation of a build (`tools/runtime/RuntimeTypeScript.targets` guards by project name, which does not transfer: the FlatBuffers project has one name in every build of it). Task 2 reads `solution.binlog`, `playtest.binlog` and `web.binlog`, records how many instances of the FlatBuffers project each graph builds and with which global properties, and names in the Code Map the exact guard the target carries (a condition on the instance, or the statement, with the log evidence, that each graph builds the project once). The target also has its own Inputs (both schemas, the project file, the pinned digest) and Outputs (the generated entry module). T8 executes the check in every required round.
- The generated entry module (`tools/e2e/.wire/curious-contraptions/wire.ts`) re-exports every `enum`, `struct` and `table` of both schemas from the per-type files beside it (`.wire/curious-contraptions/wire/<kebab-name>.ts`), uses `flatbuffers.Encoding` where the compiler writes `optionalEncoding?:any`, and carries no `any` annotation and no `no-explicit-any` suppression (strict TypeScript rule, AGENTS.md).
- `tools/e2e/workshop-wire.ts` declares no schema type; a consumer imports a generated name from the generated entry module (`./.wire/curious-contraptions/wire.ts`, a `.ts` file; the `.js` extensions inside the generated files resolve under `moduleResolution: bundler`, `tools/e2e/tsconfig.json:6`) and a helper from `workshop-wire.ts`.
- A build host, cache or digest failure fails the build exactly as S5 defines.
- The TypeScript runtime is `flatbuffers` at exactly `25.2.10` (no range) in the root `package.json` `devDependencies` and `package-lock.json`; `tools/e2e/tsconfig.json` has no `flatbuffers` path mapping, so module resolution finds the pinned package.

**Never:**
- A change to `schemas/*.fbs`, wire bytes, the C# accessors, S5's provisioning or cache rules, or the hand-written helpers' behaviour.
- A re-export of generated names through `workshop-wire.ts` or any other alias module (forward-only gate); a second generation path; a TypeScript-side post-processor script; any npm dependency other than the pinned `flatbuffers` runtime; a version range or a second source of the runtime (no Homebrew or global path).
- Running or gating the browser toolchain (`tsx`, Playwright) in a required run; the pinned runtime is installed with the other devDependencies but no required run executes the generated TypeScript; the deferral list in `tools/E2eRunner/BrowserDeferral.cs` gains, loses and re-gates no entry (only the reason text of the `run-reset-snapshot.test.ts` entry is edited, see the Code Map). The Playwright path mapping at `tools/e2e/tsconfig.json:15` belongs to the browser phase and is unchanged.
- Hashes or byte comparisons of generated output; mutants; a local Release worker build or web publish.
