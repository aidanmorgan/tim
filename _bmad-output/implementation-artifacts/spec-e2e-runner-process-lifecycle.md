## Intent

**Problem:** The e2e runner starts, waits for and kills child processes in three places (`Processes.Run`, `SuiteProcess.RunAsync`, `PreviewHost`), each with its own kill rule and unbounded waits after the kill; a program that cannot start throws an untyped `Win32Exception`; a stuck root leaves output callbacks writing to a disposed log (a thread-pool crash); the sampler's `ps` runs unbounded on the timer thread and its failures escape untyped; and the scheduler lets siblings drain the queue after a refusal and rethrows the lowest worker's failure. Two of these paths run in the required round (`ProcessesTests.CommandPastItsLimitIsRefusedAndItsWholeTreeKilled`; the dispose path of three `IdentityTests` preview facts) without tests of their failure triggers (owner decision 24r, 26 November 2026).

**Approach:** One process-lifecycle model used by all three callers (start, run to a limit, stop the tree once with one grace, sweep, drain bounded, one typed outcome), with the operating-system process handle and the process table behind two small interfaces that production implements once and tests replace with scripted fakes, so every state of the model, including a root that SIGKILL does not end, is tested deterministically. The scheduler records the first failure in time, stops sibling files and keeps an external abort distinct from a failure.

## Boundaries & Constraints

**Always:**
- **The model** (every runner-started process goes through it):

  | Step | Rule |
  |---|---|
  | Start | One private start converts a start failure (`Win32Exception`: program absent or not executable, working directory missing, the system refusing to start a process) into `RunnerError.ProcessNotStarted` naming the program and the cause, with a remedy covering every cause. No handle exists after a refused start, so nothing is stopped for it. |
  | Run to limit | The caller waits for the root's exit up to its limit (a short command's limit, the suite's wall limit or an abort, the preview's lifetime). |
  | Stop | `ProcessLifecycle.Stop` signals the root's whole tree once (`KillTree`), records a kill that throws (`AggregateException`, `InvalidOperationException`, `Win32Exception`, `IOException`) as the detail "the kill did not complete (<cause>)", and then waits for the root's exit **once**, for the grace, with no cancellation token (an abort has already been signalled), whatever the kill did. It returns `StopOutcome`: `RootState.Ended` or `RootState.StillRunning`, and the detail. No caller waits for the root after `Stop`; `Stop` is the only place a runner-owned tree is killed. |
  | Sweep | Suites only, after the root's own exit or after `Stop`, whatever its outcome: the sampler's seen processes other than the root (the root is `Stop`'s alone, never killed again) still running with the same pid and command are killed one by one (`IProcessTable.Kill(pid)`, which returns `SurvivorKill`: `Killed`, `Gone` or `Refused` with the cause; the production table maps `ArgumentException` from the pid lookup and `InvalidOperationException` to `Gone`, seen on .NET 10 macOS, run log E5, and `Win32Exception`, a refused signal, to `Refused`). The sweep goes on over every survivor; `Gone` is neither a failure nor listed as killed; each `Refused` pid, and a refused table read (no pid), is a sweep failure, all of them reported. |
  | Drain | Only when the root has ended: wait for both output streams' end of file, bounded by `max(time left before the caller's limit, grace)` (after a stop the time left is zero, so the grace). The preview has no limit, so its drain is the grace. A short command that was stopped does not drain: it refuses, and its captured text is discarded. |
  | Close | `OutputSink.Close(runner lines)` writes the runner's lines and closes, as one act under the sink's lock, after the drain, or straight after the sweep (suites) or `Stop` (preview) when the root still runs; a partial line still pending for a stream is written first, as a line (it is output received before close), then the runner's lines, so the runner's lines are the log's last lines; a chunk delivered after close is dropped and counted, never written to a closed writer. The sink itself never throws a writer fault: the first exception from its writer (a full disk) is recorded, every later write and the runner's lines are dropped and counted, and `Close` disposes the writer catching its exception into the same record; the caller, after `Close`, throws `ProcessOutputFailed` when the sink recorded a fault (unless a `ProcessNotStopped` outranks it). |
  | Outcome | A short command returns its result, or throws `ProcessTimedOut` (its limit passed and its root ended, or its output stayed open past the drain bound) or `ProcessNotStopped` (its root still ran after the grace). A suite returns its `SuiteRun`, or throws `ProcessNotStopped` naming the suite, the stop detail, the survivors killed and every sweep failure when its root still runs or its sweep failed. The preview's `Stop` throws `ProcessNotStopped` when its root still runs. Any caller's drain may also throw `ProcessOutputFailed` (its output could not be read or recorded), after the sink is closed. Among outcomes delivered to a caller, `ProcessNotStopped` outranks any other (a process the run owns may still be running). |

- **One implementation of each step.** `IChildProcess` (one production class, `ChildProcess`) exposes `Id`, `ExitCode`, `KillTree()`, `Task<bool> WaitForRootAsync(TimeSpan limit, CancellationToken)` (false at the limit; a cancelled token throws, also when already cancelled at the call, which the real handle checks first because `Process.WaitForExitAsync` returns normally for an exited root) and `Task<bool> WaitForOutputEndAsync(TimeSpan limit)`, and is `IDisposable`; every wait in the model is one of these two calls, so a fake answers and counts each wait without the clock (its answers: true, false, never, "ends when the token is cancelled", or, for the output wait, "faults with `IOException`"). `Stop` and the drain are single async methods; `Processes.Run` and `PreviewHost.Stop` are synchronous and block on them. Output: the launcher is `LaunchChild(ProcessStartInfo, IOutputReceiver)`, and `ChildProcess` reads each stream in one loop of character chunks, passing each chunk to `IOutputReceiver.Write(OutputStream, ReadOnlySpan<char>)` and calling `IOutputReceiver.End(OutputStream)` at that stream's end of file. Two receivers: `CapturedOutput` (exact text of each stream, for `Processes.Run`, whose `git … -z` output must round-trip) and `OutputSink` (splits each stream into lines at `\n`, dropping one trailing `\r`, writes a pending partial line at `End`, prefixes and writes under its lock, and raises `LineWritten(OutputStream, line)` with the raw, unprefixed line after each line, which `PreviewHost` uses for its standard-output `Workshop preview:` readiness signal, `PreviewHost.cs:90`, and suites leave unsubscribed). One read path, no mode flag; a fake delivers chunks to the same receiver. `ChildProcess.Dispose` cancels its read loops' token (disposing the `Process` alone does not end a read blocked on a pipe a descendant holds) without waiting for them; a loop ended that way passes nothing further (no `End`). `WaitForOutputEndAsync` returns true once both loops have finished, by end of file or by disposal. Any exception from a read or from the receiver (an `IOException` from the pipe, a `LineWritten` handler throwing) ends its loop and makes `WaitForOutputEndAsync` fault at once, without waiting for the other loop; the drain turns it into `RunnerError.ProcessOutputFailed` naming the program and the cause, after which the caller still closes its sink before throwing; a loop task nobody awaits after disposal is observed by a continuation, so no exception goes unobserved.
- **The grace** is one named constant, `ProcessLifecycle.Grace` = 5 s; production callers pass it, and only tests pass another value.
- **The suite log** has one format for runner lines, written by the sink's close (Close row) in this order: `E2E_RUNNER stop (wall limit <the launch's wall limit> reached | stop requested): <detail>` when the runner stopped the root; one `E2E_RUNNER survivor <pid> killed: <command>` per killed survivor; one `E2E_RUNNER survivor <pid> could not be killed: <cause>` per refused survivor; `E2E_RUNNER survivor sweep failed: <cause>` for a refused table read; `E2E_RUNNER root still running after the kill; later lines are not recorded` or `E2E_RUNNER output still open after the root ended; later lines are not recorded`. `preview.log` gets the same stop and output lines with its `preview[<port>]` prefix.
- **The process table** (`IProcessTable`; production `ProcessTable`, built with the start function and the limit) is read with one short named limit (`ProcessTable.SnapshotLimit`, 10 s) by every reader (the sampler, the sweep, the foreign-Chrome wait). A `ps` that exits non-zero or prints a row that does not parse is a typed refusal (`RunnerError.ProcessTableUnreadable`). The sampler, which runs on a timer thread with no caller, skips a sample whose read throws any `RunnerException`, counts the skips and keeps the first reason; `RunEngine` writes them to the run header (`sampler`).
- **The preview** is stopped explicitly: `PreviewHost.Stop()` (idempotent) replaces `IDisposable`; `RunEngine` calls it after the end served check and before writing the summary, and again in a `finally` for the paths that leave early (a no-op once stopped; nothing when the start itself failed); a failed start attempt stops its own process before the next attempt. When the preview's `ProcessNotStopped` meets another `ProcessNotStopped` already in flight (a suite's), one `ProcessNotStopped` naming both is thrown; otherwise an outcome of `Stop` in the `finally` replaces a failure already in flight only if it is a `ProcessNotStopped`, and any other (a `ProcessOutputFailed`) gives way to the failure in flight.
- **The scheduler** cancels an internal stop token (linked to the caller's) at the first failure of any file, of any exception type; no file starts after it; files in flight receive the cancellation; once every worker has returned, the first failure in time is rethrown, except that a later `ProcessNotStopped` replaces a first failure of another kind. A caller's cancellation (an abort) with no failure returns the results, as today; an `OperationCanceledException` from a file after the stop or the abort is not a failure.
- Deterministic tests: fakes answer each wait from a script (true, false, or never-ending only where nothing waits on it), counted per call; real-process tests use states that cannot race (a missing program, `sleep 60` under a 1 s limit, end of file after a writer that finished).
- Forward-only: one start, one `Stop`, one grace, one drain rule, one sink rule, one log format; the duplicate kill paths (`Processes.Run:50-51`, `SuiteProcess.cs:81-82`, `PreviewHost.Stop:143-152`) are deleted.

**Never:**
- A second kill or wait rule, a retry of a kill, a fallback that ignores a refused start or a stuck root, a `catch (Exception)` that hides a failure (a filtered catch that records the exception for a typed outcome the caller throws is allowed), or a CA1031 exclusion or other analyzer suppression.
- An edit to `tools/E2eRunner/Toolchain.cs` or `tools/E2eRunner/SourceIdentity.cs` (lane 2's S5c files), to `IdentityTests.TheSuiteDigestCoversTheGeneratedWireModulesAndNoOtherIgnoredFile` (`IdentityTests.cs:176-212`, S5c-2's; coordinator, 26 November 2026), to `BrowserDeferral.cs`'s list, or a new browser-deferred test: every new fact runs in the required round without tsx or Chrome.
- PATH changes inside tests, `FakeTimeProvider` or any new package, timing-dependent assertions, mutants, browser runs, hash assertions.

## Limits (outside the runner's contract)

- A process that SIGKILL does not end within the grace (uninterruptible): reported as `ProcessNotStopped`, then left; the runner does not wait or retry.
- A descendant that leaves a suite's tree before the sampler first sees it, or that holds a pipe after the sweep: not tracked; the drain records its open output in the log.
- A short command's descendants reparented after its root exits (including a root that exits at the instant of its limit, ECH15-3): `Processes.Run` keeps no process table, so they are not found; open output still ends in `ProcessTimedOut`.
- A refusal inside the sampler's own `ps` (its timer has no caller): recorded in the run header, not raised.
- The runner's own working directory, or a toolchain installation (the tsx loader, `tools/e2e/node_modules`, `node`, Chrome), changed or deleted during a run. `schemas/*.fbs` and the FlatBuffers project file are not run inputs: the suites read the generated `tools/e2e/.wire/`, which the suite digest covers (EFE17-F6, re-judged).
