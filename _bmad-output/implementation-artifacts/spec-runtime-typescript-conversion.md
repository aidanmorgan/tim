## Intent

**Problem:** Active browser isolation/bootstrap code and some runtime harnesses still use handwritten JavaScript or executable strings, despite the strict TypeScript rule. Pose shared-memory views remain exposed in worker/client code, and several harnesses infer completion from sleeps.

**Approach:** Complete the existing pinned TypeScript build for active runtime/tool sources and run harnesses against emitted modules. Encapsulate pose publication/reading behind typed atomic APIs and use explicit completion or controlled clocks in tests. Clarify the two existing isolation refusal reasons without changing activation policy.

## Boundaries & Constraints

**Always:** Preserve current worker, ring, bootstrap, persistence, clock, event and lifecycle behavior; canonical f32 values, integer identities/time and demand growth remain. All active non-C# sources in the affected runtime/tool closure are strict TypeScript with no any escape. Shipped JavaScript is generated by the pinned normal build. Test actual emitted modules through public interfaces and genuine external-boundary doubles. Keep one current publication algorithm and the C# layout authority. Preserve existing browser deferrals and source acceptance.

**Never:** No handwritten runtime JS/MJS or executable JavaScript strings, parallel legacy path, old-name alias, fallback, unconditional skipWaiting or silent waiting-worker acceptance. No output hashes/byte-identity or wall-clock sleeps as completion evidence. No browser/E2E execution, mutants, local Release worker build, web publish or CI wait. Vendor/platform code and historical evidence are not conversion inputs; do not rewrite archives or build a new compilation/coverage platform.
