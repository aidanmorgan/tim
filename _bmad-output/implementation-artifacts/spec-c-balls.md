# Finite design decisions

- **Reuse the existing dynamic-body compile.** The `WorkshopPhysicsCompiler.Compile` instance loop already emits ball body/collider/material rows from `DeclaredPhysics.Of(part)` (Dynamic, footprint-checked); `BallMaterial` is a redundant Half copy used only by validation, wire, prevalidation and mesh radius. "Adds the dynamic-body compile" = a dynamic package is admitted and carried as a generic instance. No second path. Proof: `compiled-geometry-9a16.json` `ball`/`bowling` rows DeepEqual, fixture unchanged.
- **Payload predicate, derived not declared.** Move the existing `PartRegistry.Ball` rule (Dynamic, exactly one sphere collider, no sliders) into `DeclaredPhysics.IsPayload(PartId)`, computed from the admitted entry. Game intent: receivers capture, and lesson triggers/bumpers act on, the rolling thing the player delivers; dominoes and slider bodies are Dynamic but not spheres, so they stay excluded. No new contract/schema field (that would duplicate geometry and reopen every package's bundle proof). New production identifiers must not contain package words ("ball"), or the ratchet adds rows.
- **Orderings preserved exactly.** `Targets` NamedBody and the trigger/bumper presence gate use the first payload in instance order (today `Find<WorkshopBall>`); capture sensors/guides and presentation telemetry use payloads by ascending id (zero when none).
- **No authorable parameters** (decides CAT-001 §6 by game intent): kinds teach by differing only in declared material; package `Parameters: []`; generic editor shows no panel (existing zero-parameter path).
- **Wire/save/content.** Delete `radius`/`drag`/`buoyancy` from `InstanceRecord` and `AuthoredScalar`; keep `mass`/`bounce`/`friction` (Domino-owned until 9A.32). Generalise the generic-record guard from `Threshold != 0` to every typed field (all float scalars, `enabled`, `target_count`, `half_extents`), atomically, in `MapInstance` and `WorkshopSavePrevalidation`: a forged 4 kg basketball never loads. Deleting fields renumbers later slots (as 8665e68b did; `parameters` moves 26→23): pre-conversion saves are unsupported and must be refused, never misread; no `deprecated` slots or migration. Missing declared parameters already reject (`InstanceParameterCollection.Validate` count/key check).
- **Visual radius:** delete the `MachinePart.BuildDeclarative` SphereMesh override; scenes already bake 0.34/0.28 for mesh and shape.
- **Warmup:** drop the sphere (5 ticks from y=2 fall ~1 cm, never contact; ramp precedent). Removes stale Warmup `Basketball`/`ball` rows; adds no named identity.
- **f32/scope:** generic authoring/save stays exact f32 (empty set); compiled Half lanes stay for 9A.44, not broadened. No new framework, solver or calibration.
