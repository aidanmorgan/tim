- **D14. Derivation check (revised 18 Oct 2026, accepted by the coordinator; for independent review):** evidence only from brackets ≤ 2×0.0158 ms; startup needs 16 narrow exchanges in ≤ 500 attempts (2 ms each) and derives the constant time-origin offset as the centre of the intersection of their admissible corrections, installed under epoch 0 before any requester qualifies; it refuses an empty intersection, an offset > 0.1 ms (`MaximumStartupCorrectionMilliseconds`) or an exhausted budget; the Startup record carries `startupOffset` and `admittedLower`/`admittedUpper`/`admittedWidth`. Running: ≤ 4 exchanges per check within one 2 ms timeout, slew ≤ 0.005 ms per check under the same epoch for errors ≤ 0.1 ms, re-derive under a new epoch beyond; typed `CCGPU_CLOCK_DERIVATION` records (startup, each re-derivation, the first slewed/inconclusive/unanswered check of a run, a summary every 100 checks).
- **D14 amendment (coordinator, 19 Oct 2026; Murdoch-2 R2-F3).** The startup offset is applied whatever its size. An offset beyond the declared 0.1 ms uncertainty no longer refuses the session: it is recorded once as a typed, counted `CCGPU_CLOCK_OFFSET_WIDE` record (offset, admitted interval, declared uncertainty, count; `WorkshopClockDerivation.WideStartupOffsets`). Only a derivation that cannot qualify (more than four outliers, or an exhausted budget) refuses. `MaximumStartupCorrectionMilliseconds` is deleted for `WideStartupOffsetMilliseconds`. Rationale: each worker's time origin carries its own host-clock reference (Murdoch's experiment, review-r2 §R2-6), so a host clock step could lock out a legitimate session, and the offset is corrected either way.
