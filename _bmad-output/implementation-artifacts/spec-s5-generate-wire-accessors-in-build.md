## Intent

**Problem:** `engine/gpu/WorkshopWireGenerated.cs` (6,872 lines) and `engine/gpu/WorkshopAuthoringGenerated.cs` (407 lines) are committed FlatBuffers-compiler output, regenerated by hand from `schemas/README.md` with whatever `flatc` the developer has. No build step or test compares them with `schemas/*.fbs`, so a schema edit with stale output is caught only by review, and every capability slice carries 500 to 1,500 generated lines through review.

**Approach:** The one project that compiles the accessors, `CuriousContraptions.FlatBuffers`, obtains the pinned FlatBuffers compiler 25.2.10, verifies its integrity, and generates the C# into its own intermediate directory before it compiles. The two committed files and the joining tool that only existed to make them committable are deleted, so generated C# is build output derived from the schema on every build.

## Boundaries & Constraints

**Always:**
- The compiler is the official `google/flatbuffers` release `v25.2.10` binary for the build host. The archive's SHA-256 is verified after download and the extracted binary's SHA-256 is verified before every use, both against digests pinned in the project file. A compiler on `PATH` is never used.
- The verified binary is cached outside every checkout at `$([System.Environment]::GetFolderPath(SpecialFolder.LocalApplicationData, SpecialFolderOption.DoNotVerify))/CuriousContraptions/flatc/25.2.10/<asset>/flatc`, where `<asset>` is the release archive's name without `.zip` (`Mac.flatc.binary` or `Linux.flatc.binary.g++-13`). On macOS that is `~/Library/Application Support/CuriousContraptions/...` (the path contains a space, so every use is quoted); on Linux `$XDG_DATA_HOME` or `~/.local/share`. `DoNotVerify` is required because the plain form returns an empty string on Unix when that directory does not yet exist. An empty result fails the build with an error naming the variable; the cache directory is created by the provisioning target.
- The binary is placed in the cache by rename from a temporary file in the same directory, after its digest and executable bit are set and checked, so a concurrent or interrupted build never leaves a partial file at the cache path.
- A missing, unreachable or mismatching compiler fails the build with a message naming the file, the expected digest, the actual digest where one exists and the cache path to delete. A mismatching cached file is never executed, replaced or re-downloaded silently.
- Generated C# is written only under the vendored project's intermediate output directory, is never tracked, and is never written into a source directory.
- The compiled wire surface is unchanged: the same types, members and namespace `CuriousContraptions.Wire`, the nullable `ArraySegment` byte accessors (the branch the compiler selects while `ENABLE_SPAN_T` stays undefined), the same buffers on the wire.
- Generation reruns when either schema, its build logic or the pinned compiler changes, or when its outputs are absent (a clean tree or a `--no-incremental` build), and not otherwise. It removes its previous output first, so a deleted schema type leaves no source behind. Provisioning runs only when generation runs, so an up-to-date tree builds offline and a tree that must generate builds offline from a warm cache.
- The C# static gate still refuses every compiled source in a build output directory except the SDK's, xUnit's and exactly this generated set, and it checks that set against the schemas.
- The unmodified `.githooks/pre-commit`, the five compiler-log captures, the maintainability gate and CI's existing workflow steps build from a tree that contains no generated C#.
- Any build host outside the asset table fails the build with an error naming the host.

**Never:**
- A change to `schemas/*.fbs`, to wire bytes, to the vendored runtime sources, to the domain mapping codecs (ordinary typed C# that converts between engine types and the generated accessors; not wire code, coordinator decision 38), or to the hand-coded wire that owner decision 24k assigns to `ENGINE-WIRE-ABI` (the hand vtable field counts used for unknown-field refusal, the `motion` byte vector and the non-FlatBuffers boundary layouts).
- The generated TypeScript in `tools/e2e/workshop-wire.ts` (follow-on S5b).
- A committed compiler binary, a new NuGet or npm dependency, a compiler built from source, a fallback compiler, a second generation path, or a property or environment switch that exists only so a test can redirect production inputs.
- A hash, digest or byte comparison of generated output. Integrity pins of the third-party compiler and of vendored files remain allowed.
- A local Release worker build or web publish, mutants, browser runs, or any wait on CI beyond the single check that owner decision O3 allows.

## I/O & Edge-Case Matrix

| Row | Input / State | Expected Output / Behavior | Error Handling |
|-----|--------------|---------------------------|----------------|
| M1 | Clean tree: no generated C#, warm compiler cache | Build generates one source per schema type and compiles the vendored project; every consumer builds | No error expected |
| M2 | A field is added to a schema table, then an incremental build | The built assembly exposes the new accessor without any manual step | No error expected |
| M3 | Nothing changed, then an incremental build | Generation does not rerun; generated sources keep their write time | No error expected |
| M4 | A table is removed from a schema that nothing else references, then an incremental build | The removed type has no generated source and is absent from the built assembly | No error expected |
| M5 | The pinned binary digest differs from the cached binary by one hex digit | Build fails before any generated source is compiled; no assembly is produced; the cached file is untouched | Error names the file, both digests and the cache path to delete |
| M6 | The vendored project's compile receives an output-directory source that is not a generated wire type, lacks one for a schema type, or carries an `ENABLE_SPAN_T` define | The static gate fails naming the source, the missing type or the define | Gate violation |
| M7 | A successful build, then `dotnet build --no-incremental` | Generation reruns from the warm cache and the project compiles | No error expected |
| M8 | Cold cache, network available | The archive is downloaded and verified; the binary is extracted, made executable, verified and placed by rename; the build succeeds | No error expected |
