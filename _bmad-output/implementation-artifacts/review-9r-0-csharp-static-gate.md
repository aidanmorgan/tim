# Review: Story 9R.0, Real C# Static Analysis Gate

*Reviewer: Murdoch-3 (independent adversarial review). Date: 18 Oct 2026.*

*Candidate: branch `worktree-agent-a08aebc94d551b53b`, HEAD `aad52ce` (commits `0dd495f`, `aad52ce` on base `8f682f8`). SDK 10.0.401, macOS arm64.*

*Scope: native only. No Chrome, Playwright or preview server was run. The deliverable was not changed. Every probe was temporary and was reverted, and the tree was confirmed clean afterwards (`git status`: only this review and its evidence are untracked). Raw logs are in `_bmad-output/implementation-artifacts/evidence-9r-0/review/`.*

## Verdict: **Fail**

AC3 ("a commit with a C# warning is refused") is demonstrably violated in three ways:
- a warning in the web host's own source (F1);
- a staged warning hidden by a clean working copy (F2);
- stale incremental outputs (F2).

The first two were proved with real `git commit`s that the hook accepted, both reset afterwards. The third was proved by the full hook exiting 0. In addition:
- the gate has no defence against ad-hoc suppression;
- the owner-named CA2000 control does not fire, and the spec's reason for leaving it off is refuted by measurement;
- the worker namespace refactor missed seven callers.

The verdict covers only this pre-rebase candidate. The 9.4b rebase (FlatBuffers vendoring, slnx merge, IL2125 removal) invalidates any approval, whatever the outcome here.

### The `GpuDeviceOwnership` borrow (semantic change)

**Correct.** Only the warm-up uses `Borrowed`. Its `DisposeAsync` retires the no-op `WarmupInstallation` and leaves the device to the worker's `Owned` simulation, which matches the old behaviour (the warm-up was never disposed). `WorkshopSimulation`'s constructor now rejects an undefined ownership value.

The device's `DisposeGateIfIdle` is sound for the single-threaded WASM worker:
- `Release` hands the count to a queued async waiter, so `CurrentCount == 1` only when the gate is idle;
- a call made after disposal now fails in `_gate.WaitAsync` with `ObjectDisposedException`, the same exception type as before, and holds no gate.

**Residual (Low):** on a multi-threaded host, the `CurrentCount` check and `Dispose` are not atomic. Today only the tests run there, and they pass.
