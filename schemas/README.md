# Workshop wire schema

`workshop_wire.fbs` is the one schema of every Workshop message (Story 9A.2): commands, responses (acknowledgements, physical
reads and schedule endpoints) and the construction save. `engine/gpu/WorkshopWireFlatBuffers.cs` and
`engine/gpu/WorkshopSaveCodec.cs` are its only codecs.

- Every buffer is size-prefixed and carries its root's identifier: `CCWC` (`WorkshopCommand`), `CCWR` (`WorkshopResponse`) and
  `CCWS` (`SavedConstruction`). A schema declares one `file_identifier`, so the codecs pass each root's identifier to
  `FinishSizePrefixed` and to the verifier.
- A decoder checks the size prefix, then the identifier, then runs the FlatBuffers verifier, and decodes once. A refused buffer is
  a `WireFaultException` naming its `WireFaultReason` (a save: a `WorkshopSaveRejectedException` naming its `WorkshopSaveRejection`).
- An element is named only by the bundle's string element id (`InstanceRecord.part_id`, `PuzzleRecord.inventory_part`); no field
  carries a numeric part id (Story 9A.15). A stored save is validated against the loaded bundle's elements and an unknown id is a
  `WorkshopSaveRejection.UnknownElement` refusal naming it; the worker's command decode refuses an id it has no element for with
  `WireFaultReason.UnknownElement`, naming it.
- There is no format version (owner, 21 Oct 2026): the game and its saves ship in one bundle with one schema, and bad input is
  rejected structurally.

## Regenerating the code

Use flatc **25.2.10**, the version of the vendored runtime (`CuriousContraptions.FlatBuffers/FlatBufferConstants.cs` declares
`FLATBUFFERS_25_2_10`). The release binaries are at <https://github.com/google/flatbuffers/releases/tag/v25.2.10>
(`Mac.flatc.binary.zip` on macOS). A newer flatc stamps another runtime version and does not compile.

### C#: `engine/gpu/WorkshopWireGenerated.cs`

flatc writes one file per type; the repository keeps them joined, in file-name order, inside one namespace block. From the
repository root, with `OUT` an empty scratch directory:

```sh
flatc --csharp -o "$OUT" schemas/workshop_wire.fbs
{
  printf '%s\n' '// <auto-generated>' '//  automatically generated by the FlatBuffers compiler, do not modify' '// </auto-generated>' '' \
    'namespace CuriousContraptions.Wire' '{' 'using global::System;' 'using global::System.Collections.Generic;' \
    'using global::Google.FlatBuffers;' ''
  first=1
  for f in $(ls "$OUT/CuriousContraptions/Wire" | sort); do
    [ $first -eq 0 ] && echo; first=0
    awk 'started && /^}$/ { last = NR } { lines[NR] = $0 } /^\{$/ && !started { start = NR + 1; started = 1 }
         END { while (lines[start] == "" || lines[start] ~ /^using /) start++;
               end = last - 1; while (end >= start && lines[end] == "") end--; for (i = start; i <= end; i++) print lines[i] }' \
      "$OUT/CuriousContraptions/Wire/$f"
  done
  echo; echo '}'
} > engine/gpu/WorkshopWireGenerated.cs
```

Run against the unchanged schema, this reproduces the committed file byte for byte.

### TypeScript: the generated part of `tools/e2e/workshop-wire.ts`

The e2e suites import one module. Its first part is flatc's per-type output joined in schema declaration order without the
per-file imports; everything after the `hand-written helpers` marker is maintained by hand (the frame checks, the authored-state
dump and the mock encoders) and is kept when the generated part is replaced. With `OUT` an empty scratch directory:

```sh
flatc --ts -o "$OUT" schemas/workshop_wire.fbs
{
  echo '// automatically generated by the FlatBuffers compiler, do not modify'
  echo 'import * as flatbuffers from "flatbuffers";'
  echo
  for name in $(grep -E '^(enum|struct|table) ' schemas/workshop_wire.fbs | awk '{print $2}'); do
    file=$(echo "$name" | sed -E 's/([a-z0-9])([A-Z])/\1-\2/g' | tr 'A-Z' 'a-z')
    grep -v -E '^// automatically generated|^import ' "$OUT/curious-contraptions/wire/$file.ts" | cat -s | sed '1{/^$/d;}'
    echo
  done
} > generated.ts   # then replace the part of tools/e2e/workshop-wire.ts above the helpers marker with generated.ts
```

After a schema change, also update the field listing in `tools/e2e/run-reset-snapshot.ts` (`SNAPSHOT_SCHEMA`) and the record field
lists in `CuriousContraptions.tests/WorkshopFormatTests.cs`; both tests fail until they match the schema.
