## What is a task here?

A playable slice demonstrates one named interaction through real UI, canonical Half construction, typed commands, the actual simulation worker/GPU, visible feedback and Reset. Its ABI, geometry, compiler, queue, unit tests, cleanup and evidence are supporting criteria with the same stable implementation/reviewer pair. They are not independently valuable product stories or weeks of prerequisite subsystem completion.

Aggregate rows are completion conjunctions, not a serial queue to finish before touching UI. Design decisions must settle a named uncertainty needed by the next slice, with finite inputs and an observable decision oracle. Historical checkpoints retain evidence and surviving acceptance. No row's title or a template automatically establishes INVEST readiness. The existing obligation map classifies every owner and keeps its exact source/members.

A required-now supporting criterion must have an independently reviewed result for the named slice before its dependent behavior is accepted. It cannot be waived because the parent audit is later. The complete parent remains open until all of its children pass. Conversely, an unrelated missing law/mode/device is not a prerequisite for demonstrating an already admitted part on the declared development device; it still blocks its own scope and the full release gate.

## Rolling roadmap: grow a game people can play

**One execution plan, not competing queues.** TODO owns the current slice and the next one or two; this ordered roadmap is the programme. Each slice is a thin vertical INVEST slice whose acceptance a player can observe in Chrome through Playwright, adds one generic data-driven capability or one element by declaration, and names the legacy it deletes. Physics is one generic WGSL f16 solver over the compiled initial state and animation is a separate compiled model; the [compilation model](../../gpu-f16-physics.md#compilation-model) and [game-grade envelope](../../gpu-f16-physics.md#game-grade-envelope) are fixed. Already playable: Basketball, Receiver, Ramp, Wall, Impact switch → Signal lamp, Delay (`delayed_signal` solved) and the manually constructed Bumper interaction.

**Minimum playable loop:** select an existing level whose typed goals, locked parts, inventory, connections and profiles are actually admitted, place/connect through real controls, Run, observe a meaningful unsuccessful route, Reset, change the construction, achieve the authoritative goal and visible Solved result, then Build again/Reset. Exercise save/load where supported. A Workshop mechanism with a glowing lamp is progress but does not by itself prove a level goal or a retry loop.
