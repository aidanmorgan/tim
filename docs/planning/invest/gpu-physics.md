# GPU criteria inside playable delivery

These 27 retained labels are supporting criteria or aggregate qualification scopes under existing work IDs. They are not 27 prerequisite feature projects. [Vertical delivery](vertical-delivery.md) supplies the actual visible outcomes and critical path. **This planning task makes and authorizes no code changes.** Separate execution status and owner authorization are tracked in [TODO](../../../TODO.md) and the owning implementation session. The [f16 design](../../gpu-f16-physics.md), [current contract addendum](../../engine-contracts.md), original behavioral/source criteria and stage gates remain mandatory.

For a linked consumer, implement and independently review its required-now criteria together with that playable outcome. A unit/kernel check supports the outcome and does not substitute for Chrome UI proof. A full parent remains open until every remaining consumer/mode passes. Fixed: one GPU authority, canonical Half, coarse puzzle bounds, exact discrete/Reset, typed ABI and supported-device release scope. Algorithms/layout/factoring remain negotiable. The current register has revised completion dependencies; no old horizontal edge count or harness-first order overrides it.
