# Planning audit: `spec-s6d-signal-node-route-tables.md` (S6d), fifth pass

Audited 24 November 2026, planning phase, read-only; nothing built, measured or run. Checkout `spec-drafts`, code at main `25df3cd5`. Binding decisions: `docs/planning/elements/readiness/owner-decisions-2026-11-22.md` (22, 24h, 37, 38). Contract lines are cited as `S6d:<line>`. Word count 1,771 (limit 6,000).

## Verdict: Fail

Six blocking defects. Three are inside `<intent-contract>`. The owned scope leaves the goal evaluator, the goal content reader and several node-kind ladders out, so the story's closure ("every chain is a table") fails for these two enums; the table's location and handler shape are unstated and cannot work across the project boundaries as drafted; and "every value has exactly one row, refused as today" does not fit the values that today are explicit refusals or share a default arm.

### B2. Table location, key and handler shape are unspecified, and cannot work as drafted (design; Sufficient)

- **Where:** `S6d:24`, `S6d:80`.
- **Defect:** One table "keyed by `ActivationNodeKind`" whose "row holds the signal operation, event kind, declaration-field rule, duplicate-emission rule and per-stage handlers" is read by `CuriousContraptions.Bundle` (`SignalBundleValidation.cs:112`), `CuriousContraptions.Abstractions` and `Abstractions.Signal` (`SignalContracts.cs:17`, `EventDescriptor.cs:51`) and by the engine. The bundle and Abstractions projects cannot see engine types, and the handlers are stage code over the network's private state and `Span` arguments (`RouteOccurrences`, `QueueContacts` take `Span<ActivationLatch>`, `Span<ActivationMemory>`, `ref int count`), which cannot be arguments of `Func<>`. The bundle validator and the compiler switch on descriptor **class** (`SignalNodeDescriptor` subtypes, `WorkshopActivationCompiler.cs:51`, `SignalBundleValidation.cs:114`), and the descriptors' enum is `SignalNodeKind` (10 values, `Kind` property), not `ActivationNodeKind` (11): the two enums differ (`LevelIndicator` and `StickyFirstInput` both come from `Indicator` through `IndicatorKind`, `WorkshopActivationCompiler.cs:99-102`).
- **Fix:** Add a "Row shape" paragraph: "Abstractions: `ActivationNodeKindRow` data table (`FrozenDictionary<ActivationNodeKind, ...>`) with columns signal operation, published event kind (and the timer completion-policy column replacing the nested switch), memory holder, level source, may-source, may-target, required declaration fields, sensor identity field; read by `ActivationMemory`, `SignalTopology`, `SignalObservationRules`, `EventRecordProducer.KindOf`. Abstractions: a `SignalNodeKind` table keyed by the descriptor's `Kind` (so the bundle validator and compiler key on the enum, not on the class), with the per-descriptor validation and compile functions as static methods taking the descriptor; `SignalNodeDescriptor.Kind` becomes the one class-to-enum map. Engine: the per-stage handlers stay private members of `ActivationNetwork`; its stage dispatch is a `FrozenDictionary<ActivationNodeKind, StageHandlers>` of custom delegate types with `Span` parameters (not `Func<>`), static, built once." If this is judged too large, the contract chooses and states the reduced shape (rows as data only; stage branches reduced by extraction), but the choice is made in the contract.

### B3. "Every value has one row, refused as today" does not fit the values that are explicit refusals or share a default arm (wrong specified behaviour; inside the intent)

- **Where:** `S6d:29`, `S6d:46` (N3), `S6d:139`.
- **Defect:** Several defined values today have no route and several lookups run before the guard that refuses an undefined value. `SignalTerminal.Output` is not an input terminal: `WorkshopActivationCompiler.Edges` throws "Unsupported input terminal." (`:36-42`) and `ActivationNetwork.cs:131-137` throws "Unsupported terminal." for any `PortRole` outside three. `PhysicalRequestTargetKind.None` throws "Unsupported physical request target." (`WorkshopActivationCompiler.cs:63-68`). `ActivationOccurrenceKind.TimerElapsed` is routed by the default arm `_ => ActivationNodeKind.Timer` of `ValidateOccurrence` (`ActivationNetwork.cs:759-768`): a "no default row" rule needs an explicit row. `SimulationEvents.Domain(None)` throws "No event record has this kind." (`EventDescriptor.cs:57`). `WorkshopGoalKind.None` is valid only when the goal is `default` (`WorkshopPuzzle.cs:19`). Each site's refusal differs in type and text (`Operation` and `KindOf` throw `ArgumentOutOfRangeException` with different messages; the constructor refuses with `ArgumentException("Invalid activation node declaration.")`). `ActivationMemory.Holds(_nodes[i].Kind)` (`ActivationNetwork.cs:63`) and `ValidateContactBindings` (`:78`) run **before** `Enum.IsDefined(node.Kind)` (`:96`): a throwing lookup there changes the refusal type for an undefined kind.
- **Consequence:** A table with exactly one row per defined value and one miss behaviour either changes today's refusal at some site or cannot be written; N3's test through the real path only reaches the pre-existing `IsDefined` guards, so the table's miss branch has no executed test and passes on the baseline.
- **Fix:** In `S6d:29` replace the last clause with: "A defined value that is not a route (`SignalTerminal.Output` as an input, `PhysicalRequestTargetKind.None`, `SimulationEventKind.None`, `WorkshopGoalKind.None` with a non-default goal) has an explicit refusal row reproducing today's exception type and message at each site; `ActivationOccurrenceKind.TimerElapsed` has its own row; lookups used as predicates before admission (`Holds`, `ValidateContactBindings`) use `TryGetValue` and answer `false`, as today; a lookup that today throws throws the same exception type and message; an undefined value is refused where it is today (`:96`, the `Defined` checks), and the table's own miss branch is unreachable past those guards and is verified by reading the diff, as in the first S6 slice's AC3." Rewrite N3 (`S6d:46`, `:139`) as the real guards: undefined `ActivationNodeKind` refused by `new ActivationNetwork(...)` with "Invalid activation node declaration."; undefined terminal and role by `Edges`/`ValidateEdges`; the defined refusals above asserted by type and message.

### B5. N4 cannot be run "for each kind" (test; inside the intent)

The three admitted cases are the three arms of `RouteOccurrences` `:481-491`; they become the row's duplicate-emission rule (admit-set of occurrence kinds per node kind).
