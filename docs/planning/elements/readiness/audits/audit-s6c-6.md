## Blocking findings

### B1. The shared driver row cannot express the two sites' reference rules, and "the one difference" is false (wrong specified behaviour; inside the intent)

- **Where:** `S6c:25` (Approach), `S6c:32` (Always, last sentence), `S6c:63` (the `[Flags]` set), `S6c:65-66`.
- **Defect:** The contract says both sites "read the same driver rows" and that one difference stays (store with finite work). Reading both ladders there are at least six more:
  1. `ElectricalSocket`: the compiled site requires `SupplyNode` set (a `LogicGate` node, `WorkshopCompiledScene.cs:245-246`); the bundle site requires `binding.SupplyNode` absent for it (`SupplyBundleValidation.cs:185`, `sourceRead` false) and instead requires `Socket` (a port) (`BundleValidator.cs:247-251`). A single `SupplyNode` flag on the row would demand opposite things at the two sites.
  2. `Supply`, `Charge`: bundle reference is `SupplyNode` (a source descriptor); compiled reference is `track.Source` plus `SourceCapacity` equality and owner (`:233-243`). The row's flag list names both `SupplyNode` and `Source` (`S6c:63`) and the compiled `Source` is not a `PresentationBinding` field.
  3. `WheelAngle`: bundle `GuidePort` (port with rope guide role, `BundleValidator.cs:252-255`); compiled `Guide` (rope guide id owned by the body, `:299-305`).
  4. Signal drivers: bundle `SignalNode` (`:197-199`, plus `SignalBundleValidation.cs:91-97`); compiled `Activation` node plus `SignalObservationRules.Supports` (`:313-320`).
  5. Bundle-only descriptor-kind checks with no reference field: `Oscillator` and `OscillatorPulse` require an oscillator descriptor, `Count` a pulse-count descriptor, `SurfaceDeflection` a compliant-surface payload (`BundleValidator.cs:260-268`, errors `Presentation.Oscillator`, `.PulseCount`, `.CompliantSurface`). They are neither payload members nor reference kinds, so after the change they would stay as `driver is X` ladders in `PresentationBindingCapabilities` (the very member measured at 20), against Design note 6 (`S6c:123`) and Never "a second classification path beside a table" (`S6c:38`).
  6. Bundle-only: `PresentationBindingEvents` checks that the event kind is declared by the package (`:355-356`); the compiled site has no such check.

  Also unstated: the old ladders check both directions (reference present iff driver requires it). "One loop over the driver's references" (`S6c:25`) checks only the required direction unless the loop is told to refuse a set reference the driver does not require.
  `SupplyBundleValidation.cs:183-190` is described as "payload checks" (`S6c:65`); it is the supply-node and socket source-reference check (`Presentation.Source`, `Presentation.Socket`).
- **Consequence:** An implementer following the text builds a single flag set that is wrong at one site (case 1), leaves three descriptor-kind ladders, or drops the absent-direction check, which loses a protection (B2).
- **Fix:** Replace `S6c:32` last sentence and `S6c:63` reference column with: "The driver row names reference concepts, not binding fields: `ElectricalSocketPort`, `RopeGuide`, `AirflowSource`, `GasShape`, `IntegrityObserver`, `FiniteWork`, `EnergyStore`, `Retention`, `Transmission`, `ActuatorCoordinate`, `SupplySource`, `LogicGateNode`, `SignalSource`, plus a descriptor-kind column (`None`, `Oscillator`, `PulseCount`, `CompliantSurface`, read by the bundle site only). Each site owns one existence table keyed by concept; a concept with no entry at a site is not carried at that site (bundle: `LogicGateNode`). Each site loop (a) for each concept the driver requires: refuses a missing reference and a reference whose existence function fails; (b) for each concept the driver does not require: refuses a set reference (the two directions of today's `driver == X != field.HasValue`). The `Event` row carries a `SimulationEventKind`-keyed sub-table with exactly two entries (`IntegrityBroken` requires `IntegrityObserver`, `FiniteWorkReleased` requires `FiniteWork`). The differences kept as each site's own existence functions are listed in the Code Map: `ElectricalSocket` (bundle port, compiled port plus logic gate node), `Supply`/`Charge` (bundle descriptor, compiled source slot, owner and capacity), `WheelAngle` (bundle guide port, compiled guide id), signal drivers, the compiled store with finite work, and the bundle-only event-declared check." Add `SignalBundleValidation.cs:91-97` to the Direct consumers (it calls `SignalSource` and `SignalObservationRules.Supports`; signatures unchanged). Classification: wrong specified behaviour.
