## Choosing and completing a scope

[Bill Wake's INVEST method](https://xp123.com/invest-in-good-stories-and-smart-tasks/) guides the boundaries: aim for an independently useful outcome, retain room to negotiate its implementation, state its value, make scope and uncertainty understandable, keep it small, and give it observable acceptance. Real dependencies are compatible with this method. It is not an automatic score or proof that a story is ready.

- **Independent:** one behavior, defect or invariant with its necessary caller/content/test closure; preserve genuine prerequisites. Never force independence by introducing a parallel runtime or postponing an unsafe ownership cutover.
- **Negotiable:** algorithms, representation and interaction details may be discussed inside the fixed target architecture, source behavior, typing and quality gates. No new compatibility shim, old-name alias, fallback, dual authority or automatic format migration.
- **Valuable:** identify the player-visible result or concrete enabling invariant. Native compiler/evaluator correctness has stage-appropriate value; it does not claim actual worker/browser release.
- **Estimable:** identify actual affected owners/callers, finite modes and one specific unknown. Do not invent time estimates. Resolve an unknown in one bounded decision/experiment with an oracle and named implementation next; a measured rejection can finish an optional compilation experiment, never waive required workers.
- **Small:** do one demonstrable behavior/invariant. An audit/qualification/release parent is a conjunction, not a ready feature. Choose its named element, law, current consumer, fixture, defect, device/workload or level child. Do not merge multiple new elements into a publication.
- **Testable:** keep every original positive, negative/control and boundary criterion and required build, real Chrome/Playwright, Reset/save, lifecycle and publication stage; performance budgets are release-checklist gates. State independent expected behavior before implementing; exact source behavior clauses override a shortened card summary; explicitly superseded backend/precision/sequencing clauses follow the current design authorities.

Use the original canonical work ID for existing ownership/checker context, and a card label to identify the bounded scope within it. Labels are not new WorkOrderIds, aliases for old runtime values or an extra schema. D/I/CLEAN/U/F/V/status/evidence remain identifiable supporting criteria with the same implementation/reviewer pair through fixes. Their review still happens at its required stage. No fresh administrative task/pair is needed.

The surviving planning documents are navigation and ID preservation only; the [ordered roadmap](invest/vertical-delivery.md#rolling-playable-roadmap) and each slice's own stated prerequisites govern criterion completion, and where retained row wording conflicts with the current authorities the authorities govern. Historical edge counts are not required equality. Do not collapse grouped owners into a new serial graph: design/native/UI/closure criteria occur at different stages, and a naïve quotient can create false cycles. Internal prerequisites still require independently reviewed stage proof; external prerequisites require their applicable Pass. Former execution-predecessor navigation is not a technical dependency. Existing tools/readers/CLI meanings are unchanged; no new generator or automated INVEST approval is required.

At every actual cutover, record the sole target owner/path, complete current callers/content updated, old route/input removed or rejected, and proof it cannot remain reachable. Each development target has one admitted GPU capability surface and rejects unsupported current content explicitly. Preserve a usable Free workshop entry; the build remains incomplete and cannot claim release equivalence. Join inseparable required behavior/caller changes within that vertical; do not wait for all domains before a giant cutover. Do not ship unused DTO scaffolding as completed behavior. Historical source appendices retain evidence and surviving acceptance, not old architecture, 75-level targets, obsolete schema support or instructions to rerun dead processes.
