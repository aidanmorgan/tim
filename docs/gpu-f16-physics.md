# Canonical f16 game values and authoritative WebGPU physics

Owner decision: GPU-F16-DESIGN-2026-10-02, 2 October 2026. This is the current numerical and execution design. The owner explicitly accepts coarse, puzzle-scale physical precision for performance and chooses one canonical f16 game-value model across authoring, content, saves, messages, presentation models and physics. Implementation and qualification status, including the admitted development surface and unresolved failures, are tracked in [TODO](../TODO.md). This design asserts no measured speedup.

This document defines canonical Half game values and sole WGSL f16 numerical authority. The [engine contracts](engine-contracts.md) define current ownership, protocol, lifecycle and clock rules. Physical laws, puzzle coverage, typed identity, forward-only changes, exact construction Reset/save, independent review, browser proof and P0-035 qualification remain required.

Physics follows the [general data-driven engine contract](engine-contracts.md#general-data-driven-engines): typed element declarations select reusable physical capabilities, never element-specific solvers or catalogue-keyed equations. Missing behavior extends the general engine within its consuming slice; specialized general kernels remain valid.

## One authority

The independent simulation worker owns a WebGPU adapter/device, compute pipelines, buffers and queue. WGSL compute implements authoritative continuous mechanics, constraints, collision/query geometry and numerical electrical, optical, acoustic, fluid, thermal and radiation models. It also computes numeric sensor predicates. C# remains the host/compiler/tooling language where viable: validated construction, typed command admission, integer ticks/IDs, discrete controllers/events, transactions and goal transitions consuming committed GPU results. A CPU calculation must not override a physical result or serve an unported numerical domain.

The animation worker remains separate. Main-thread 2dog/Godot WebGL rendering consumes committed read-only presentation data. WebGL is the renderer, not the physics compute API. There is no CPU solver fallback, optional production backend switch, dual ownership, automatic format migration or legacy protocol interpretation. Missing WebGPU or the separate required `shader-f16` feature is explicit unsupported capability; every already-required device/browser tier remains a qualification requirement. Unsupported required tiers block release rather than disappearing from the support matrix.

A CPU editor preview is non-authoritative. Placement admission, overlap, sweeps, material boundaries and optical/acoustic/detector queries use the same quantized GPU geometry and typed identity contract as Run. External numeric text/API values are parsed and quantized once on entry to the canonical game model; the UI displays the admitted canonical value. They cannot supply a second production spatial oracle.

## Numeric representation and admission

All authoritative continuous floating state, iterative solver arithmetic, dot products, reductions and law evaluations use concrete WGSL f16. No f32/f64 force accumulator, constraint solver or hidden CPU correction is permitted. This is a new algorithm/representation implementation; mechanically casting the current finite-difference Newton/line-search solver is not an accepted design.

The following explicit exceptions do not create a second solver:

| Value | Representation and boundary |
| --- | --- |
| Identity, topology, material/mode tags, counts, iteration/tick/epoch/sequence | Typed integer values; closed sets are C# enums and validated generated numeric shader ABI discriminants. |
| Spatial coarse origin | Signed integer cell coordinates, cell width exactly 1/16 metre. This is an explicit physical representation component, not an ID. Local primary position is f16 in [-1/2, 1/2) cell units; its physical unit is 1/16 metre. Crossing a cell renormalizes the origin and local offset together. |
| Units/scales | Typed dimension and signed integer power-of-two scale exponent per compiled quantity group. Scaling metadata is immutable during an admitted transaction; a changed scale is an explicit recompilation/revalidation. |
| Canonical game values and durable saves | C# Half wrapped in dimension-specific value types through editor controls, construction, configuration, content, animation/read models, fixtures and tools; WGSL f16 for physical arithmetic. Current resources and construction saves serialize canonical half bits plus typed integer scales/cells losslessly through explicit codecs; do not assume Godot Export/Variant supports Half directly. Quantize at the explicit input boundary, not again differently at Run. Save is construction-only; Reset restores its exact canonical bits. |
| Scheduling and platform boundaries | IDs, ticks, counts, palette byte identities and indices keep their correct integer types. Host/browser clocks and required Godot/API arguments may be wider at explicit boundaries. Authored animation curves/state, geometry/material values, machine settings and difficulty/nudge/goal thresholds remain typed Half; CPU cosmetic operations explicitly round their declared results back to Half (no claim that every library instruction is native half). Kernel dt is f16 under its declared scale. Widening f16 to render f32 is exact but cannot recover precision already lost. No wide stored game model or physical feedback. |
| Reference testing | Higher-precision analytical/offline oracles and read-only performance clocks/statistics are permitted outside game authority. Immutable host copies of committed raw f16/integer state are checkpoints, not CPU simulations. |

No previous floating format is accepted as a compatibility input. Forward-convert current authored resources, editor/property controls, previews, serialization, fixtures and tests together in their owned slices; reject obsolete schemas explicitly. Input quantization itself loses precision. Using one representation avoids inconsistent repeated conversions, not that first loss.

**Simple integration representation:** one integer cell origin plus one f16 local-position lane; no persistent compensation lane, exact-product machinery or higher-precision correction. During a tick, use a bounded f16 displacement relative to that tick's starting local frame for substep evaluation, then compose/quantize the committed local pose once. This ordinary candidate displacement is discarded at commit; it is not a hidden cross-tick remainder. Carry k=floor(p+1/2) advances the integer origin and sets p=f16(p-k), with +1/2 advancing and -1/2 staying. All affected query kernels consume the same current candidate pose. WGSL-permitted rounding, contraction/reassociation, promoted implementation and subnormal flushing are accepted only where the declared puzzle outcomes pass. We do not demand a strict compiler rounding trace or add dispatches merely to materialize arithmetic.

Cell-local coordinates reduce absolute-position quantization; they do not solve every small increment, long lever arm, cancellation or underflow problem. Relative frames must be chosen before narrowing, using integer cell differences and bounded f16 local arithmetic. A far-field or long-span calculation must satisfy its own admitted scale and error budget. Do not convert a 64 m absolute position to f16 and then subtract it to recover a small gap.

Initial mechanical admission profile: one puzzle unit U is the existing authored metre unit; position bounds [-64,64] U per axis, collider extent at most 16 U, linear speed at most 64 U/s and mass from 1/1024 through 1024 kg. The retained constant-velocity spike's 0.01–1 U/s matrix is a unit control only. The first playable Basketball uses its canonical radius 0.34 U and gravity 9.81 U/s² under the general admitted 64 U/s speed bound; it does not inherit the spike's 1 U/s ceiling. Each mechanism declares its smallest meaningful geometry, motion and activation margin in canonical puzzle units; there is no universal millimetre target. These are declared design limits to validate, not claims that every current declaration already fits. Zero/static state has an explicit typed representation. Existing required content outside this profile remains a blocking content/representation obligation; it cannot be silently clamped, dropped or assigned a CPU path. Other quantities and cross-domain coupling require a finite typed scale/range declaration before their individual law slice can become ready.

For each operation, per-kernel declared operand/count bounds, straightforward static arithmetic checks and guarded operands must establish normal finite representability **before** division, reciprocal, square root, product or accumulation. Normalized nonzero stored operands should lie within [2^-10,2^8] where the declared unit permits it; kernel-specific intermediate bounds must remain within the binary16 normal finite range. Guards handle zero denominators, impossible ranges and exhausted iteration budgets with typed candidate failure before mutation/publication. A post-hoc NaN test is insufficient: WGSL permits indeterminate results after some runtime floating errors. Subnormal persistence is never assumed; an increment below the admitted puzzle resolution may quantize to zero only when its source-specific required behavior/control remains correct; otherwise repair the scale or authored mechanism in its existing slice before admitting it. No silent saturation or clamp-to-valid behavior.

## Accepted puzzle-scale error contract

The owner rejects a millimetre/submillimetre precision goal. The replacement is clear, stable puzzle behavior at canonical f16 resolution, not a close reproduction of every old double trajectory. Each current law/part/mode/fixture owner freezes its intended success, negative/control, activation margin and geometric clearance before acceptance. The same typed placed construction and command sequence must preserve those outcomes. Content whose intended distinction collapses after quantization is explicitly re-authored/requalified in its existing owner scope, or remains unsupported and blocking; no hidden tighter solver, automatic clamp or silent dropped puzzle.

Each named playable fixture uses the following deliberately coarse limits with its declared characteristic spans/speeds; the earlier one-unit-body spike remains only a reference control. They are chosen acceptance policy, not measured capabilities; tighter numeric limits require a named gameplay reason and a separate approved refinement, never inheritance from an old double residual:

| Quantity | Accepted puzzle-scale check |
| --- | --- |
| Visible position/trajectory | Maximum Euclidean error <= 5% of the fixture's declared characteristic moving-part span over the complete Run. For an independent 1 U reference body the bound is 0.05 U; Basketball uses its declared 0.68 U diameter, not an invented one-unit size. The reference starts from the same canonical input; input quantization is reported separately. |
| Contact/query behavior | Intended hit/miss, support, ordering and activation controls must pass with the declared puzzle clearances. Temporary interpenetration must not exceed 10% of the smaller participating body's declared characteristic span or cause a wrong outcome. No universal distance-residual/millimetre gate. |
| Speed and orientation | Speed error <= 10% of the declared characteristic speed, with zero-motion controls judged by visible drift and outcome; orientation error <= 5 degrees unless a named mechanism demonstrably needs a different admitted angular resolution. |
| Energy/work/finite stores | Complete-Run signed balance error <= max(Q, 0.05 * (E0 + Win + Wout)). Q is the law's declared smallest meaningful transfer quantum in canonical scaled units, frozen before testing. E0 is initial nonnegative stored/kinetic/declared potential energy relative to a fixed reference; Win/Wout count external boundary transfers once. Internal circulation is excluded. Zero initial available energy plus zero supplied work cannot sustain useful work or trigger the energy-dependent outcome; legitimate initial/gravitational energy may be released. |

These are broad physical approximation budgets, not permission to alter discrete puzzle semantics or add a fresh allowance each step. Future circuit, light, sound, thermal, fluid and radiation slices choose their quantity scales/meaningful quanta using their exact source outcomes and controls; they do not inherit arbitrary mechanical units or an old microscopic residual. Thresholds and any hysteresis are declared canonical game values, not tolerance hacks.

For the current generic mechanical Run ledger, use metres (U), kilograms, seconds and joules, with a fixed potential datum p0=(0,-0.4599609375,0), the authored workbench plane at canonical Half(-.46) U. For constant gravity g, U=-m*g·(p-p0), and E=U+0.5*m*|v|²+0.2*m*r²*|omega|² for the admitted solid sphere. Gravity is internal to this potential and is not counted again as supplied work. Freeze Q=2^-10 J as one complete-Run reporting quantum, not a per-step allowance, collision cutoff or gameplay threshold. These static-surface witnesses have Win=0. Wout counts independently derived nonnegative drag loss m*k*integral(|v|² dt), impact restitution/friction loss from the declared impulses and pre-impact contact velocity (including angular response), and sustained friction work at the contact point. Do not define Wout from observed endpoint energy loss. Report the signed residual Eend-E0-Win+Wout against the complete-Run bound above; zero available energy and zero supplied work still cannot produce useful work.

Exact integer identity, events, causal order, transaction commit, canonical construction Save and Reset remain exact. Same-environment replay binds adapter/driver/features/shader/compiler/pipeline and deterministic reduction order. Cross-device qualification compares intended outcomes inside the admitted puzzle envelope; it does not promise bitwise physical equality.

The current generic integration profile derives local elapsed seconds by dividing the bounded integer/phase offset by the exactly represented admitted physical rate, currently480Hz. It does not multiply a long elapsed ordinal by a quantized reciprocal. Canonical stored linear velocity remains cells per 1/512 second; the declared kernel adapter converts it to U/s by multiplying by32 and converts back at committed boundaries. The independent reference uses exact rational 1/480-second substeps from the same canonical input. The active default simulation cadence is120Hz with four substeps; animation and presentation default to60Hz, with internal typed configuration retained. The [shared-clock cadence contract](shared-clock-cadence.md) admits configurable real commit rates only through explicitly coupled physical profiles: the initial targets 60/120/240 Hz execute eight/four/two of these 480 Hz substeps per commit. Quantized numerical dt is not exact time. New commit groupings require affected same-time numerical, energy, contact, history and resource proof; changing only a scheduler delay is not configurable simulation. A different physical substep frequency requires its own typed Half dt, complete time/phase equations and qualification before admission. Every solver method has a bounded dispatch/iteration budget and typed failure behavior. Shared-body updates require exclusive writes, coloring or deterministic staged reductions; no assumed f16 atomics or cross-workgroup spin barriers. A bounded GPU contact/constraint slice selects a method for the accepted coarse envelope; casting the old finite-difference Newton solver is not the plan.

## First reusable mechanical capability

The current cutover replaces the specialized Basketball/workbench law with one generalized engine path. Catalogue definitions compile typed bodies, collider geometry, materials, force parameters and residence sensors; numerical dispatch uses motion/shape/feature types, never a catalogue ID or Receiver-presence branch. Basketball/workbench and Receiver are acceptance witnesses of that same path. Initial capacity is 16 bodies (at most one dynamic sphere), 32 static/dynamic colliders, 16 materials and eight residence sensors. Static planes and rigid boxes are the first supported collision partners. Unsupported pairs, non-rigid/sheared transforms, capacity excess and numeric-domain violations reject the whole candidate before publication; the wider required shape/affine capabilities remain explicit later obligations.

Free flight stores an immutable segment origin, canonical launch velocity, gravity vector, linear-drag coefficient and physical start ordinal/phase. For elapsed seconds t, x=k*t, a=g-k*v0 and P(x)=1/2-x/6+x²/24-x³/120+x⁴/720, the declared motion is p(t)=p0+v0*t+a*t²*P(x), with derivative v(t)=v0+a*t*(1-x/2+x²/6-x³/24+x⁴/120). WGSL f16 evaluates both; C# only authors/validates declarations. The first force domain has speed at most64U/s, gravity magnitude at most16U/s², k in[0,.125]/s and primary segment age at most one eighth of a second. Re-anchor at contact/force changes and absolute multiples of60 physical ordinals in the current480Hz profile, after emitting the prior positive-duration interval, using the same canonical primary state. This fixed binary-time segmentation is independent of commit grouping and is a representation choice, not a different force law. No retained compensation lane or per-body host trajectory exists. Polynomial truncation bounds do not qualify Half evaluation; actual coarse outcomes remain required. Rotation uses the same canonical angular state and normalized quaternion product. Below binary16 minimum-normal angular speed 2^-14, evaluate the continuous small-angle turn as (omega*t/2, 1) without dividing by speed; for t<=2 s its omitted cosine/sine terms are below 2^-29 and 4e-14. This changes no angular state or physical speed threshold. Normal-speed evaluation and quaternion validation remain unchanged; the C# render-only decoder evaluates the same exponential in its external presentation adapter.

Materials explicitly carry canonical restitution, bounce threshold and friction. The pair law is product restitution, maximum threshold and the product of the two square roots for geometric-mean friction, with declared Half operations. Basketball authors(.55,.1,.3), Receiver surfaces(.12,.1,.3); these values are data. Generic solid-sphere inertia is I=.4*m*r². Impact normal impulse is -m*(1+e)*min(vNormal,0), using zero restitution below the pair threshold; the tangential impulse includes contact-point angular velocity and is projected onto the Coulomb disk. Contact order is stable collider/feature identity. Four projected-impulse sweeps accumulate unilateral normal and tangent impulses; unresolved residual/penetration rejects rather than treating exhausted iteration as success.

Persistent support resolves new instantaneous impacts first, obtaining v0/omega0. For remaining interval h, form v*=v0+(g-k*v0)*h and omega*=omega0, then apply only accumulated-impulse deltas during the four support sweeps. From their v1/omega1, use aEffective=(v1-v0)/h and alphaEffective=(omega1-omega0)/h. Supported motion is exactly p(t)=p0+v0*t+.5*aEffective*t² and v(t)=v0+aEffective*t: gravity/reaction is applied once. A matching retained contact or just-resolved inelastic contact with zero normal external acceleration remains eligible for the coupled support solve: friction at another contact can load it. Unowned neutral contacts do not acquire support, positive separating acceleration releases ownership, and the existing gap/velocity bounds and nonnegative normal-impulse projection still apply. Separate/rebuild the manifold on outward motion or feature change. Zero-duration geometric correction uses at most four closest-normal projection/requery passes, with total displacement from the original hit point capped at radius/64 across all passes. Repack canonical cell/local coordinates after each pass; reject unresolved hit penetration or excessive overlap with another collider. The incoming velocity and material impulse remain unchanged, the next motion anchor owns the corrected point, and the earlier positive-duration piece stays intact. Correction credits no residence time and rechecks eligibility on both sides; its potential-energy change remains signed ledger residual. Rest is supported zero motion, not a global speed clamp or a part-specific floor case.

Contact search uses the same generic trajectory and quantized shape query, an outward gap enclosure and a downward-rounded advancement step. A128U/s profile bound covers the admitted free-flight polynomial and supported quadratic; actual Half bounds must be checked before operations. Restitution activates only at a nonpositive queried gap; the radius/64 overlap/correction band is not an early-contact surface. A whole-interval strictly closing-normal certificate remains complementary: it includes curve-specific acceleration, outward travel and the shape-query uncertainty span before treating the positive right endpoint as the minimum. A strictly negative upper bound on distance acceleration also retires a positive-gap concave interval. It includes convex-distance curvature, the same guarded normal-variation span and the interval-derived free-polynomial acceleration factor; zero drag and supported acceleration use factor one. These independent geometric certificates are complementary bounds inside one collision search. Remaining positive near-surface intervals use directed bounds of the same canonical primary polynomial and rigid shape declarations. Integer-cell and local-position terms remain separate through the closest-face and radius subtraction. Squared clearance is evaluated as a factored dominant-axis term plus the other outside-axis squares, avoiding subtraction of nearly equal squared distances. For a convex static box, the squared-distance Hessian is bounded by twice the identity, including closest-feature changes; a whole-interval chord lower bound uses outward speed, shape-distance and acceleration bounds. The endpoint calculation encloses its polynomial/transform arithmetic rather than treating the rounded shape-query scalar as exact. Scale guards precede the products; unproved endpoint or near-field bounds retain subdivision/rejection. Speed bounds use the curve-specific outward acceleration allowance over the current interval and the declared f16 arithmetic allowance. This method remains subject to actual puzzle-outcome qualification, not a universal compiler rounding proof. Near an indeterminate gap, bounded interval subdivision replaces an unsafe positive step. Each physical substep has at most64 advancement/subdivision operations and eight impacts. Exhaustion/ambiguous unsupported contact fails the complete candidate. The implementation freezes its contact band and outward arithmetic before numerical admission; required fast/edge witnesses must work within the budget.

A residence declaration names its frame and target body, open local bounds, strict relative-speed limit, canonical dwell duration and enabled state. Intersect eligible intervals from the actual motion polynomial (including its derivative extrema/piece boundaries), splitting at impacts, support changes, bounds and speed crossings. A per-sensor per-substep budget of128 root/subdivision operations fails atomically on exhaustion. Exit, speed equality/excess or disable resets residence; open-boundary tangency contributes no time. Store the physical start ordinal/phase and compare the actual canonical dwell, including Half(.35)=.35009765625s, without rounding it down to physical ticks. Emit once for continued residence; Reset restores construction and clears elapsed/event/latch state. Presentation consumes the committed event/state. Timed cosmetic effects use the independent generic animation evaluator.

A typed planar guide declares a static frame/local pose, one dynamic sphere target, inclusive local position bounds, lower-support height and margin, and maximum acceleration. Its descending-only law is `−A·(x,0,z)/max(1,length(x,z))` in that frame; sphere support is local centre Y minus radius. Catalogue code supplies declarations only. The current capability admits one guide per target and A≤12. The shared force-driven quadratic uses a midpoint acceleration over at most one 1/480 s physical step, with static-frame transforms and the same coefficient record in physical queries, CCD and presentation. Contacts use that force in the coupled support/friction solve. Membership crossings split and reanchor within the existing event budget; no position nudge, hysteresis or widened capture volume substitutes for the force.

Guide arithmetic bounds verify division and square-root endpoints with directed multiplication, rejecting if the bounded verification cannot establish an enclosure. The interior model uses conservative acceleration≤37, intermediate speed<64.125 and jerk≤776 solely for error bounds; the committed speed limit remains64. A nonrepresentable crossing retains an enclosing phase bracket and adds its force uncertainty to every affected point of the piece. Earlier bracket uncertainty carries through subsequent CCD/read pieces until the canonical physical-step checkpoint. Within that step, a reached crossing may retain its exact guide/component/boundary identity only while the error-bearing curve proves monotone departure; impacts, extrema or uncertain direction invalidate ownership. Root, event and ownership-capacity exhaustion still reject the complete candidate. Stored motion certificates are local to that checkpoint, not a global trajectory proof: qualification compares the accumulated whole-Run trajectory with the unchanged oracle from the original launch. Unsupported state/motion schemas, invalid certificates and exhausted root/contact/piece budgets reject the complete candidate. Current First principles nonzero-guide qualification remains in progress in TODO.

The forward generic state ABI is version 4, 18,576 bytes: the 9,344-byte scene/state prefix (including eight immutable 64-byte planar-guide slots) plus a 16-byte motion header and 72 ordered 128-byte motion pieces. Each successful commit records its positive-duration free-polynomial, supported-quadratic or force-driven-quadratic intervals, with original anchor/cell/local/quaternion, velocity/angular velocity, force/drag or effective acceleration, exact admitted physical rate and physical ordinal/phase boundaries. The timing field carries exactly Half480 for the current typed profile and both GPU and browser divide elapsed ordinal/phase by it; old reciprocal-bearing pieces are rejected. The bound is eight admitted substeps times at most eight contact/membership events plus a tail; overflow rejects the whole candidate. Admission/Reset has no preceding motion. The v9 Workshop response is 9,744 bytes and carries those committed pieces with its pose and discrete capture state. Browser sampling evaluates those declared curves and angular paths, forces the original whole-commit endpoints, and holds when an adjacent commit or covering piece is missing. It never substitutes endpoint interpolation, a shortest quaternion arc or a browser contact solve.

The current Workshop trace is a 128-byte projection of one dynamic pose/orientation/angular state and at most one capture latch, including exact epoch/tick/profile identity. Its 7,201-record reservation is 921,728 bytes. The pose collector remains Diagnostic-only. Both Production and Diagnostic reserve 7,200 binary64 host-clock duration slots (57,600 bytes) and a 1,024-byte encoding scratch buffer; their retained timing payload is 58,624 bytes, and Diagnostic's combined pose/timing payload is 980,352 bytes. Each successful automatic tick records the Advance-through-EmitRead critical-path wall span, including GPU waits, validation, packing and publication enqueue; reliable acknowledgement/display latency, scheduler waits and the final duration append remain outside that span. Native allocation/retention checks do not establish a WASM overhead bound or exclusive CPU time. Original millisecond values are emitted in at most 128-value chunks at the acknowledged stopped transport barrier. Begin also flushes a prior sealed capture before reusing the bounded buffer and before the new RunLoop starts. Timing schema v2 binds epoch/profile, the encoded canonical construction/session/projection, terminal reason, contiguous tick count and Complete/Incomplete status; missing, duplicate, out-of-range, negative or nonfinite timings cannot qualify a complete run. Earlier timing schemas are historical observations, not current input. It does not claim to retain interior motion or the full generic scene; unsupported diagnostic composition becomes an incomplete capture without rejecting physics. Full motion fixtures retain their original GPU records separately. Receiver capture feedback is an instantaneous generic opacity endpoint declaration in the shared Animation evaluator. Browser application requires the matching selected committed occurrence/world and retains its original physical feedback stamp; Reset retires that world target and restores zero. No timed world-animation capability is inferred from this step effect.

Acceptance includes unchanged intended Ball/workbench outcomes, Receiver floor settling/capture, real side/rounded-edge contact, fast crossing, open-boundary/exact-speed negatives, exit/re-entry, wrong target/disabled controls and exact Reset. A separate engine fixture changes material, geometry, gravity and drag and composes unfamiliar declarations without shader/solver edits. Historical specialized-law evidence is regression input, not qualification of this replacement.

## Transaction, protocol and resource lifecycle

One forward protocol revision replaces physical F64 fields with explicit packed f16 bits, typed scale/cell data and integer metadata. Specify byte layout, endianness, padding, finite-domain validation and enum mappings; unknown tags/versions are rejected. Keep 64-bit identities/ticks exact through their documented integer word layout. WGSL lacks C# enum syntax: generate validated numeric ABI definitions and domain-specific wrappers from the canonical typed declaration, keeping raw numbers at that boundary rather than introducing string selectors.

Simulation owns candidate and committed buffers. Commands are acknowledged as applied only after the required dispatch, validation and result transfer complete and the whole epoch/tick commits. CPU discrete results and GPU numerical state publish together; queued Run is not a running state. Bound in-flight work and queues; the worker remains responsive while awaiting GPU completion. Reject late generation/epoch results after Reset/Load/disposal.

Before publishing a commit, retain the raw state needed for the declared recovery policy. Device loss discards the candidate and enters a typed fault state; a retained immutable last-committed host checkpoint may restore only the matching state on a newly qualified device. If the checkpoint is absent or environment identity changes, require Reset/requalification; never claim rollback from lost buffers or silently continue on CPU. Run/Pause/Step, Reset, construction Save/Load, worker crash, GPU loss, cancellation and disposal each retain their own acknowledgement and rejection controls.

No standard shared WebGL/WebGPU buffer is assumed. Measure actual readback/copy/publication costs with the existing renderer. Compute and rendering share a physical GPU; the existing GPU/frame budgets cover their combined workload, and the complete simulation tick budget includes dispatch, synchronization, validation and transfer. Kernel timing alone cannot close performance qualification.

## Delivery order and cutover

The planned playable sequence starts with [Basketball drop/contact/Reset through the actual Workshop](planning/invest/vertical-delivery.md#ball-drop), then Receiver capture, construction Save/Load, the existing First principles ramp/capture goal and switch-to-lamp activation. **This planning task makes and authorizes no code changes.** Separate execution status and owner authorization are tracked in [TODO](../TODO.md) and the owning implementation session. The [GPU cards](planning/invest/gpu-physics.md) are required supporting criteria inside these consuming outcomes, not a standalone harness programme.

The first runnable target admits the named Basketball/workbench surface, routes it solely to GPU authority and retires its reachable synchronous numerical entry path in the same change. Startup must retain a usable Free workshop entry when authored level 0 is unsupported. Each later vertical admits its additional exact part/mode/content and removes its affected old route together. Unit/kernel harnesses remain useful supporting controls; they are not playable delivery or a substitute for real UI.

Unsupported current declarations reject visibly before mutation and remain individually owned requirements. This development target is explicitly incomplete, not a claim that all previously released behavior is preserved. No CPU/GPU selector, mixed numerical domains or delayed all-domain runtime switch is permitted. Per-part/mode/fixture proof remains identifiable, and P0-030/031/034/035 still require every current content, law, device, lifecycle and performance obligation before full engine release. The revised current register removes obsolete horizontal prerequisites; required-now criteria must actually pass within each vertical.

P0-007 CPU convergence work against superseded tiny tolerances stops. Retain its physical invariant tests, failure captures and high-precision code as explicitly non-production reference evidence where useful; do not claim the old implementation meets the new target. Optimize one measured bottleneck at a time after correct f16 behavior exists. The design decision is committed; speedup and device qualification remain to be demonstrated.
