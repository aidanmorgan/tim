# Complete-attempt measurement recipe and arithmetic oracles

## Preparation and capture

Freeze source/diff/bundle/worker hashes, fixture configuration/typed topology, device manifest, build mode, expected terminal reason and thresholds before capture. Record cold startup separately on the20Mbps/50msRTT profile; then allow12wall seconds after usable UI. Warm for **at least10wall seconds of active time in preceding complete UI attempts**. A timeout warm-up is a full3600-tick attempt; an early-goal warm-up repeats complete attempts until10wall seconds accumulated. Retain every attempt and Reset boundary. Verify exact construction restoration; then press Run again and begin a **fresh** measured attempt at acknowledgedstart/tick0.

S002 already prescribed Reset before fresh measured runs and forbade cross-Reset interval joins. This contract makes complete warm-up attempts, wall-clock minimum, early-goal minima and thermal gap/duty explicit. It does not attribute within-run trimming or stitched FPS to that historical text.

For each workload/device take3 matched production/diagnostic pairs, in the predeclared order P/D,D/P,P/D. The builds have identical source/configuration except diagnostics; preserve both hashes and report overhead, never subtract it from production. For a claimed before/after optimization, freeze seeded random pair order before measurement: seed3003, pair1 before/after, pair2 after/before, pair3 before/after; retain this literal order (the seed is provenance, no unspecified PRNG). Match topology, solver, storage, clocks, properties, algorithms, workload/actions, thermal/power/viewport/refresh and instrumentation except the single declared change. Combined changes are labeled combined; no worker-versus-storage attribution without an isolated control.

Each active capture begins at Run acknowledgement, includes first throughlast tick and all stalls, and ends at the actual observed goal/timeout stop boundary. Capture monotonic wall timestamps, clock origins/mapping, attempt/world/generation IDs, applied start/end tick and terminal reason. No inference from RAF or FPS. Record request→acknowledgement and stop→Reset separately, retaining them in raw timeline. No implicit “warm-up cut” from the measured interval. Unexpected input, hidden tab, source mismatch, concurrent build/test, overwritten records, missing boundaries or unknown identity cannot yield an accepting capture; preserve failure and stop cause. Ordinary GC/shader/solver stalls remain active.

Timeout criteria: expectedTimeout, appliedtick0→3600, >=29.7wall seconds and>=1000 distinct presentation observations, plus all performance gates. A slow60000ms attempt still has complete3600tick coverage but fails simulationrate .5. The observation deadline is180wall seconds; preserve and diagnose the same interrupted attempt, never silently retry or extend game timeout. A missing stop atdeadline is Incomplete coverage and retained failed/deadline behavior.

Early-goal criteria: expectedGoal, fulltick0→actualgoal, minimum240ticks,1.98wall seconds and100 distinct presentations. Each of3 pairs must individually meet minima; pooling short wins cannot create adequate observations. Earlier success is valid observed behavior but **Incomplete performance evidence**, never the3600-tick timeout case. This applies to the compliant receiver and any separately named early-goal fixture. Independent expected outcome takes precedence: an unexpected goal in a timeout fixture is Fail, not a shorter successful benchmark.

The preparation above applies to running-physics attempts. For stopped idle/animation workloads, keep physics stopped throughout: complete one prior30-wall-second stopped interval with the same declared cosmetic actions, retaining its own capture identity and raw timestamps. This exceeds the10-wall-second warm-up minimum without a Run. Use ordinary hide/show or fixture start/stop controls to restore the declared initial cosmetic state, verify construction unchanged, and begin a fresh capture identity at monotonic time T. Do not reset a clock by a state setter or count warm-up samples in the fresh interval. Stopped thermal capture starts a fresh300000ms timeline after that same warm-up. These captures have no3600-tick claim, Run acknowledgement or simulation-rate verdict; future CHECK-METRICS/AGGREGATE implements their distinct capture schema. P0-003's AttemptObservation arithmetic helper is explicitly for running-physics attempts, not a stopped-capture qualifier.

Stopped idle/animation captures use30continuous wall seconds and>=1000 distinct observations when active animation is being qualified; idle may legitimately render no new frame and is judged idle invalidation/resource/input behavior, not fake60FPS. UI/camera/animation activity must invalidate correctly. A stopped capture is not a Run and never claims3600ticks or simulationrate.

The strict arithmetic boundary accepts monotonic timestamps from0 through1,000,000,000,000ms and positive attempt durations from0.000001 through180000ms. These finite representation limits prevent overflow; they do not change the runtime timeout or allow a partial attempt to qualify. Out-of-range evidence and null packets reject as InvalidDataException, not an unhandled arithmetic/null-reference fault. A contract may strengthen the frozen minimum observations, never weaken them. Known unexpected terminal outcomes remain Fail even when other boundaries are missing. Hidden thermal failure likewise cannot be downgraded by a later missing span.

## Presentations, intervals and slots

Only actual distinct compositor-presented application frames qualify delivery. Capture platform/browser trace with a stable presentation identity and presentation timestamp mapped to the Run clock. A renderer-submitted frame, repeated frame ID, RAF callback, screenshot, video encode frame or animation sample is not automatically a displayed frame. Current telemetry lacks this proof; P0-028/034 must establish it. If the available trace cannot identify distinct delivered app frames, presentation qualification is Incomplete even if RAFlooksfast.

For target H=60 or90Hz, freeze scheduled deadlines at RunStart+n×1000/H ms, n=1…ceil(duration×H/1000). Slots are (previousdeadline,deadline], with the final partial slot ending exactly atstop. Keep that partialslot; do not discard it to improve rates. A distinct presentation is counted once and occupies its containing slot. Multiple presentations in one slot increase actual delivery count but occupy onlyone slot; duplicates never do either. Requiredfps=distinctcount/(fullend−start)×1000. Missedfraction=(scheduledslots−occupiedslots)/scheduledslots. Requirefps>=.99H andmissedfraction<=.01 separately. A physical display faster than thetarget retains its actual presentation observations; never synthesize90Hz callbacks on60Hz hardware.

Retain every interval between distinct presentations plus the leading RunStart→first and trailing last→stop boundary durations; these conservative boundary intervals are part of pacing percentiles. Nearest-rank percentile index=ceil(p×N)−1 aftersorting; reportcount,p50,p95,p99,max,mean. Frame interval gates supplement rate/slotgates; a missed burst may fail rate while p99 stillpasses. Unknown/missing first/last boundaries are Incomplete.

Exactslot arithmetic rehearsals use one common timestamp origin. Cross-context mapping uncertainty must be<=1ms forfreshness, with value±error checked against the budget; overlapping budget boundaries are Incomplete. Slot assignment needs either the same traceclock forRun/deadlines/presentation or rigorous occupied/missed lower/upperbounds that agree on verdict. This row's arithmetic helper conservatively returns BrowserPacing=Incomplete for any nonzero mapped uncertainty; CHECK-METRICS/AGGREGATE may later implement the specified interval-bounds oracle, never assume errorzero. SyntheticRehearsal and AnimationFrameCallback always return BrowserPacing=Incomplete. A declared CompositorTrace enum alone is not authenticated evidence: independent review must inspect rawtrace, device/capture method and sourceidentity.

Actual trace identity and slot mapping are external observability prerequisites, not permission to claim that repeated callbacks count as frames. GPU-unavailable and CPU-attribution-unavailable gates remain separately Incomplete.

## Noise, uncertainty and scoped regression

Each repeat is an observation unit; thousands of correlatedticks are not thousands of independent trials. Report individualrun distributions and min/max range across the3 pairedattempts. For any claimed scalar improvement letdelta=before−after, and U=max(full before-repeat range, full after-repeat range, twice clock/error bound). A gain is established only if **every paired delta>U** and all required-now end-to-end/correctness/absolutegates pass. Equality or overlap is Incomplete as a gain, never roundedup. No percentiles are added and no diagnostic overhead is subtracted. For proportions use actual integer denominators; forzero-allocation/count invariants anypositive failure isFail, not noise.
