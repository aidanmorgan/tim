# Current engine boundaries and protocol requirements

This contract is used with [canonical IEEE-754 f32 game values and WASM SIMD physics](gpu-f32-physics.md), the [simulation–presentation bridge](simulation-presentation-bridge.md), [performance budgets](browser-physics-performance.md) and [current source acceptance](planning/requirements.md). It states the current target directly. [TODO](../TODO.md) owns implementation status. A frozen work-order approval or design fixture does not qualify the current runtime.

## Ownership and assemblies

The browser owns construction interaction, Scene Graph authoring, input, and final property application. A portable typed compiler validates immutable construction and transforms the Scene Graph into flat, value-only declaration tables for the Physics Graph. The independent simulation worker owns discrete commands, controllers, transactions, reliable publication, and the unified physics engine: a high-performance C# WebAssembly runtime leveraging 128-bit SIMD (`wasm-simd128`) to execute numerical motion, forces, dynamic AABB BVH spatial queries, contacts, Box2D v3 Temporal Gauss-Seidel (TGS) Soft constraints, multi-domain networks, and energy stores. It publishes committed poses directly into a lock-free zero-copy triple-buffered ring in `SharedArrayBuffer` using atomic sequence counters, eliminating GPU-to-CPU readback stalls. The independent animation worker owns cosmetic phase and procedural effects, running at 60 Hz fed one-way by committed physics results. Browser rendering follows the display clock (30–60 FPS), issuing instanced draw calls (`gl.drawElementsInstanced` in WebGL 2, `renderPass.drawIndexed` in WebGPU) reading directly from the shared pose ring.

Every mutable field, map, cache, buffer and property has one writer and an explicit lifetime. No Godot object/reference or live scene read enters worker contracts. Preserve full authored affine geometry/material semantics; a convex affine transform cannot silently become a normalized rigid pose. Validate singular/unsupported transforms and numeric local-coordinate bounds before installation. Queries, broadphase, colliders, support footprints, swept corrections and presentation all bind the same typed geometry identity/revision. Replace collider geometry/material/participation and query metadata atomically; restore old metadata with its snapshot.

Retain specialized timer/controller arrays, animation slots/versions/free lists, spatial hierarchies and transaction participants inside their correct owners. No ECS or new storage platform is a prerequisite. Every current component override, internal body, fixture, material, shape and direct/transitive query consumer participates; a representative part cannot close the owner audit. Compiler, host, solver, animation and presenter cutovers update current callers/content/tools together and remove obsolete routes. Never create backwards compatibility shims, helpers, or bridges; all refactoring is forward-only.

## General data-driven physics and animation engines

The [general-engine execution design](general-engine-design.md) specifies declaration records, compiler admission, WASM SIMD128 dispatch, shared animation, and presentation. Its [complete source composition map](planning/general-engine-element-map.md) retains every planned source and explicitly owned model gap; a mapping is not runtime qualification.

**Tri-Graph Architecture and Compile-to-State.** The engine decouples into three independent graphs with clear responsibilities and one-way synchronization:
1. **Logical Scene / Machine Graph:** Main-thread authoring model. Represents hierarchical puzzle elements, typed sockets, logical connections (wires, belts, pipes, axles), UI selection, and serialization. It handles user interactions, drag-and-drop placement, rotation, and connection wiring without knowing solver internals or GPU vertex formats.
2. **Physics Graph:** Compiled at Run from the Scene Graph into flat, contiguous Structure-of-Arrays (SoA) SIMD-aligned memory tables. Represents rigid bodies (mass, inertia, velocities, transforms), colliders, Box2D v3 TGS Soft constraints, force regions, finite energy stores, sensors, and multi-domain network nodes across mechanical, electrical, optical, acoustic, and pneumatic domains. Advances at a fixed 120 Hz tick with 480 Hz substeps on a dedicated WebAssembly SIMD worker. Designed to support hundreds of concurrent puzzle elements with sub-millisecond execution times.
3. **Rendering Graph:** GPU-instanced draw batches on the browser main thread. Groups static and dynamic meshes by material and geometry into instanced arrays. Consumes interpolated transforms from the zero-copy `SharedArrayBuffer` pose ring and cosmetic secondary animation offsets from the Animation worker. Fully compatible with both WebGL 2 and WebGPU.

**One-Way Data Flow.** Data flows strictly one-way: physics → animation → renderer and physics → renderer; nothing flows back. Rates are ordered: physics (120 Hz with 480 Hz substeps) > animation (60 Hz) ≥ renderer (30–60 FPS, display-paced). Physics always updates faster than rendering, and rendering never influences physical results.

**Never implement a per-element solver or animation evaluator.** Elements supply typed declarations: geometry, bodies, materials, constraints, stores, sources, sensors, controller operations, animation curves/tracks, transitions, and target bindings. Shared physical laws and shared animation evaluators consume those values. Catalogue/part names, IDs, or concrete classes must not select equations, collision responses, sensor algorithms, or cosmetic update loops; instance IDs identify state and bindings, not bespoke behavior. Adding a new puzzle element means adding its declaration data (the physics capabilities it instantiates, parameters, art, and animation bindings) and nothing in the solver or the animation engine.

When a required element exposes a missing capability, extend the reusable engine law, sensor/controller primitive, or animation evaluator with explicit typed parameters and independent acceptance. Deliver that extension with the current consuming slice; each later physical domain is added as a generic capability inside the slice that first needs it, never as an element-specific path, and no universal framework is built first. Domain-specialised capability kernels selected by declared data are valid; element-selected kernels are not. Element-specific assets, shapes, parameter values, and declarative compositions remain valid; hidden executable callbacks or element-keyed branches do not become data merely by being registered.

Animation definitions use reusable typed curves, tracks, state, and transitions driven by admitted commands, committed physical observables/events, and the shared clock. The Animation worker evaluates them; the browser binds and applies results to element-specific art. Physical/contact-bearing motion remains Simulation-owned. No per-element worker switch, private cosmetic scheduler, or presentation feedback into physics is permitted. Preserve canonical IEEE-754 `f32` values, WASM SIMD128 physical authority, separate workers, lifecycle, and single-property ownership.

For each affected capability, inspect the declaration-to-execution path and prove it with varied parameters/instances or an unfamiliar declaration composition, plus a meaningful negative/control and unsupported-input rejection. Within an already supported capability, a differently named element must need only declarations/bindings/assets and its proof, with no solver/evaluator source edit. A genuinely new capability needs its general engine extension and proof first. Retain every named element's actual UI, Reset/save, lifecycle, performance, and publication criteria; reuse proof only under the existing applicability rules. All refactoring is forward-only; zero backwards compatibility shims are permitted.

## Stable identities and construction

A construction owns a nonzero 128-bit DocumentId and monotonically allocated nonzero U64 identities. Typed entity, body, collider, joint, connection, capability, observable, target and goal IDs share the document allocator; deleted values are never reissued. Allocation is transactional and exhaustion rejects. A failed unpublished candidate restores the allocator exactly, with no escaped ID.

Definitions declare explicit stable U32 member keys, never array ordinals. Persist typed child IDs by member key/kind; movement, save/load, recompilation and storage compaction preserve them. Matching key/type may survive a definition replacement; absent members retire and new members receive new IDs. Slots, tree traversal, Godot instance IDs, runtime handles and hashes of display names cannot become public identity.

Definition, geometry and puzzle registries use typed U64 IDs with exact registry SHA256 handshakes; adding entries cannot renumber existing ones. Worker session is 128 nonzero bits. Positive signed-I64 world/query generation (at most I64.MaxValue) qualifies installed IDs; Reset/Load retain authored IDs but invalidate old-generation references. Animation has separate positive U64 generations and independent standalone-UI registrations. No counter wraps.

Compile in explicit stable order: entity/member, connection, capability, observable, target/property. Contact order uses ordered body/collider pair then declared feature identity, including equal-time events; broadphase/packing order must not select numerical reduction order. Preserve replay within the qualified same environment; cross-device numerical outcomes use declared IEEE-754 f32 bounds and exact discrete order.

Construction includes document/registry/allocator/puzzle identity, precision/mode/environment, every entity/definition/locked state/pose and declared initial root/internal-body motion, typed parameters/member maps, assistance knots, typed connections and goal predicates. All floating game quantities store standard IEEE-754 f32 floats (single-precision 32-bit floating point). Every required field appears exactly once; reject missing/duplicate/unknown fields, undefined enum values, invalid identities and collapsed numeric controls. No arbitrary property bag, inferred default or old-format migration.

Maximum construction is 1 MiB with 4096 entities, 8192 connections, 256 goals and 4096 placement targets; stricter admitted workload budgets may reject explicitly, never drop content. Generic qualification fixtures are not limited by an unrelated Workshop UI cap. Exact field layouts and new protocol/content version numbers are required reviewed P0-008/P0-016 decisions before a variant is admitted; the retired F64 byte layouts are not a current schema.

Parameter declarations retain every named field/unit and mode: ball radius/mass/restitution/buoyancy/drag/rolling resistance; wall dimensions; ramp dimensions; pipe length; receiver threshold; clock interval; counter integer target; pressure minimum mass; Hold/Delay duration; weight mass; spring stiffness/damping/precompression; trampoline tension/damping; clutch close duration; cannon capacity/charge power; motor speed/torque; wound-spring stiffness/stroke/lead; battery enabled; pusher stroke/speed/acceleration/force; conveyor dimensions/surface-per-radian; bumper strength; fan supply/force/reach/width; bellows force/reach/width; windmill response; lever mass/initial angle. Their current named model/source criteria own ranges. Logic And/Or/Xor/Nor/Nand, all eight optical colours, three tone bands and both 45°/90° bends remain distinct modes.

## Wire and admission

Use little-endian exact U8/U16/U32/U64 and signed I64 where declared, strict Boolean 0/1 and explicit enum tags. JS uses exact BigInt/DataView operations for 64-bit identities/ticks, never Number or JSON numeric conversion. External diagnostic U64 is exactly sixteen lowercase hex digits; session text is thirty-two; I64 decimal has no plus, padding, leading zero or negative zero. Domain logic never parses these external forms.

All physical/game-value payloads carry standard IEEE-754 f32 floats; validate finite values and preserve canonical admitted representations. Do not normalize rotations or reconstruct wide hidden state in a codec. Platform clock readings retain declared integer nanosecond adapters. Resource/presentation UTF-8 is strict, NUL-free and bounded to 4096 bytes; strings do not select domain behavior.

Each envelope identifies version, message kind, total length, actual sender/recipient role, outbound/return leg, session, world generation, edge sequence, commit tick/revision, topology revision and BufferId. No pointer, closure, heap view, scene object, local slot or executable declaration crosses the boundary. Validate checked lengths before allocation, then schema/route/session/generation/discriminants/intrinsic values/identity before mutation; reject truncation, trailing bytes, unsupported flags, unknown tags and conflicting duplicates.

Required message families are Hello/Ready/Fault/Credit/Acknowledge; simulation commands/results; complete physical samples, occurrences and topology; query/results; construction/transfer seal/save; animation definitions/commands/results/samples; clock probe/reply; diagnostics. Hello/Ready match build/schema/registry hashes and actual role. A physical sample is complete coherent state, never a partially installed delta. Cold topology/construction transfers install only after contiguous exact chunks, bounded complete length and digest seal; failed decode preserves the installed world.

Admission, application commit, recipient application and durable save are separate outcomes. Requests retain original generation/sequence, target identity, required revision/dependency, application tick/phase/order and exact immutable payload. Duplicate pending/terminal/already-acknowledged inputs preserve their original meaning; conflicting duplicate, gap, stale generation, late/far-ahead target and capacity shortage reject explicitly. No automatic retry turns a lost reply into a second effect. ExactTick requires committedTick < T ≤ committedTick + 1200, with no silent rescheduling; future pending commands cannot block due controls. DependencySequence names a lower admitted same-generation command and must have Applied before execution; retain dependency satisfaction before result acknowledgement. Failed/cancelled or unresolved-at-exact-tick dependency yields DependencyFailed. Same-tick inputs compare one common pre-tick revision and commit one tick/revision/result transaction. Replay is bounded to the admitted 30-second Run (1800/3600/7200 ticks at 60/120/240 Hz) and 65536 records; recording overflow is explicit incomplete evidence and cannot alter physics.

A current codec requires a complete field/width/unit/route/length table for every admitted variant, canonical enum mappings, exact command/query/animation result and cancellation rules, independent malformed/extreme/2^53-neighbour/stale-slot fixtures and current caller compilation. P0-016 owns this forward ABI work; unadmitted variants remain explicitly unsupported. Old protocol and save versions reject rather than supplying defaults.

## Reliable storage and leases

Every edge direction has separate caps of 56 data leases/504 KiB and 8 control leases/8 KiB; a control allocation is at most 1024 bytes. Categories cannot borrow. The lease ledger records original edge/session/nonreused BufferId/sequence/bytes/category and ownership phase. Transfer detaches the buffer; exactly one context or transport owns it.

Return the same allocation as Credit, with validated identity, original charged length and explicit zero padding. Return consumes no reverse-edge credit and receives no further Credit. The original edge stays charged through the whole round trip. Reuse allocates a fresh identity; stale returns cannot release it. Free pooled and leased allocations both count. Fan-out charges each copy.

Process returns before new outbound messages. A receiver must return a request without waiting for a reverse response lease; reserve reliable result/event storage before physical commit and send retained semantic responses when capacity exists. Control saturation must still permit returns/acks. Fault is a bounded sticky typed record with exact repeated-fault count, not an unlimited queue. Reliable occurrences/results do not coalesce; monotonic acknowledgement watermarks may.

Six 512 KiB edge pools, three 1 MiB transfer staging buffers and 2 MiB aggregate retained wire copies/packing scratch give the 8 MiB transport budget. That last 2 MiB is Simulation 1 MiB, Animation 768 KiB and Browser 256 KiB. Count limits never authorize uncounted payload bytes. One pending inbound object per recipient is at most 1 MiB. Simulation retains at most 128 ordinary and 8 lifecycle requests/results; queries at most 64 total across two generations; occurrences at most 1024 retained/staged per required recipient. Lifecycle batches contain at most 8 requests; ordinary/query/animation request batches at most 32. Current f32 byte-layout arithmetic must also fit these fixed quotas and pass simultaneous saturation controls.

Transport Return does not release a semantic request/result. Results and queries retain original generation/sequence and required/read revision until contiguous acknowledgement. Query Cancel has its own slot/result and its target resolves once; Reset cancels pending queries while completed terminal outcomes remain unchanged. Topology installation acknowledgement is distinct from transfer-disposal acknowledgement; state delivery waits for installation.

Animation requests route only browser→animation; unsupported simulation/animation reverse routes reject. Controls wait for registration acknowledgement. Animation applies admitted browser requests before physical-feedback evaluation.

Animation UI/world streams share one aggregate 128-entry request/result pool and at most two retained result generations, not separate allowances. Retire/acknowledge the old world generation before admitting new-generation results; UI remains live within the same caps. Navigation replaces world then UI without a third result window. Target/property claims never overlap; attempted external instance IDs are not reused.

## Lifecycle and atomicity

Host modes are Building, Running, Paused, Completed and Faulted. Completed retains runtime state for display after goal or the declared Run limit; it is not editable construction. Session phases are Starting/Ready/Recovering/Disposed/Unsupported; transition phases are Idle/Preparing/Committing/AwaitingRecipients. Browser operation outcomes distinguish admission, commit, application, completion, rejection and indeterminate process loss.

Startup uses a fresh session, generation 1, revision 0, tick 0 and empty validated Building construction before explicit initial ReplaceConstruction. No user command is admitted before matching readiness and clock/capability checks. Return/ack/fault handling remains available during barriers. Cancel discards only precommit candidates and cannot undo an installed world. New Reset/Load cannot overtake prior completion or exceed retained-generation bounds.

WASM solver completion and validation precede publication/commit. Device loss follows the same explicit fault boundary; runtime memory buffers are not a recoverable save.

## Clocks, histories and performance

Use one continuous session master clock owned by Simulation, with context-local monotonic integer nanoseconds only as calibrated measurement/wakeup adapters. All subsystem pulses derive from its admitted epoch and typed cadence configuration; no per-Run or frame-delta clock is an independent scheduling authority. The complete [shared-clock and configurable-cadence contract](shared-clock-cadence.md) defines exact rational pulse ordinals, lifecycle projections, supported rates, forward configuration admission and proof. The active defaults are 120 Hz simulation/four 480 Hz physical substeps, 60 Hz animation and 60 Hz presentation, with no player frequency controls. Retained internal configuration supports 60/120/240 Hz with eight/four/two actual physical substeps, independently selected animation and presentation cadences, and no dropped physics. Timers/display callbacks only wake scheduling. Future default changes require affected qualification; alternate internal profiles do not gate the active default merely because the protocol can represent them.

Map browser↔simulation and browser↔animation separately. For probe b0,w1,w2,b3 and per-timestamp quantization bound q, require nonnegative round-trip residual and ordered stamps. Offset interval is [w2−b3−2q, w1−b0+2q], expanded by 500 ppm elapsed drift; map each sample with its own uncertainty added once. q/sample uncertainty must be at most 100,000 ns and mapped halfwidth at most 1 ms. Collect eight valid probes, ten milliseconds apart; retain eight, select narrowest current interval/newest tie, refresh normally every 250 ms; one outstanding probe expires after 250 ms. Mapping expires at 500 ms. Recalibration cannot shrink an already retained sample's uncertainty; actual measured clock mapping error must also be at most 1 ms. Disjoint updated intervals require fresh calibration; no interpolation across generation/counter discontinuity.

After initial qualification, test availability through the next 250 ms refresh horizon using the retained intervals: at least one must remain within the 500 ms lifetime and its drift-expanded full width plus twice the maximum admitted sample uncertainty (200,000 ns total) must be at most 2,000,000 ns. A lost horizon enters the typed Recovering state before current mapping is necessarily lost. Recovering retains the eight slots and display epoch; currently usable captures/history remain admissible only under the unchanged current-time uncertainty, identity, no-borrow and coherent-bracket rules. Old, future or wrong-generation capture rejection alone cannot start recovery. Recovery uses the existing 10 ms minimum probe spacing and one-outstanding-probe rule. A qualifying accepted interval restores normal Ready cadence. Each episode permits at most eight new probe sends and 250 ms elapsed; after the eighth send, its outstanding reply may settle only within the remaining episode bound, with no ninth send. If the episode remains unqualified when its final reply settles or its time bound expires, fault explicitly without automatic re-entry. Existing disjoint/expiry generation transitions remain. This recovery rule adds no uncertainty allowance, age exception or extrapolation; actual physical-feedback age must still pass the 50 ms bound.

All physical bodies and moving reference frames sample one committed display timestamp and admitted trajectory, including interior angular motion/full turns. Dependent simulation-clock cosmetics use that same physical time; autonomous UI uses the continuous shared-master session projection, independently of world pause. Physical-feedback age retains the referenced simulation capture stamp; a fresh animation timestamp cannot hide old feedback. Boolean/enum/event state is step-valued at the matching commit; scalar physical quantities hold unless their registered definition explicitly allows interpolation. The renderer interpolates each body between the two bracketing committed substep poses (linear position, shortest-arc normalised quaternion) sampled directly from the lock-free zero-copy triple-buffered pose ring in `SharedArrayBuffer` using atomic sequence checks. A missing bracket/mapping holds the prior complete coherent world display; no extrapolation or per-body time clamping. Pause/Completed/Step apply matching committed endpoints and reseed; Resume excludes paused elapsed time. Use the fixed 16,666,667 ns display delay and the zero-copy triple-buffered ring under the [configured-cadence capacity and exhaustion rules](shared-clock-cadence.md#history-capacity-and-unchanged-ceilings).

Simulation executes at most four whole ticks per scheduler turn, yielding for controls; animation at most one current-time evaluation. Each turn services returns, up to eight controls and eight data envelopes round-robin before bounded work. More than 100 ms simulation debt enters explicit stopped Capacity failure at last commit. Reliable/history age above 50 ms is a performance failure; unresolved reliable stall at 500 ms stops the world, missing liveness at 1000 ms faults the session. No timeout drops terminal results or pretends completion. The current reliable-stall condition covers both sent requests and leased terminal ACKs within the existing two-slot limit. Arrival and byte retrieval do not release a lease: C# must validate the complete response/command identity and applicable cursor/history admission first; a valid terminal ACK that no longer owns presentation still releases its own lease. Only that completion recomputes the remaining work and can clear the condition. Simulation receives both boolean transitions; clearing the transport condition never clears an already latched world Fault, which still requires Reset. Unknown, duplicate or invalid receipts cannot release capacity or clear newer unresolved work.

Hidden tabs request Pause normally; suspended delivery is not an invented acknowledgement. Foreground recalibrates/reseeds and stays paused/faulted until explicit recovery. Present-once effects retain bounded reservation until actual visibility receipt or explicit removal/Reset; expiry alone is not receipt. Reduced motion changes only declared cosmetics.

Prove exact positive/control/boundary behavior, delayed/duplicate/reordered/saturated traffic, pre/postcommit failure, crashed worker, stale generations/leases/slots, leaked resources and recovery through actual Chrome workers. Preserve P0-003 measurement/device/workload limits and all P0-034/P0-035 gates; unavailable hardware or unresolved fields remain incomplete. The [performance plan](browser-physics-performance.md) and [measurement criteria](planning/requirements.md#measurement-contract) supply the current full measurement recipe.
