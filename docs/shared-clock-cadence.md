# Shared clock and configurable subsystem cadence

This is the current intended design for the user-required common clock. Implementation and qualification remain open. It replaces independent elapsed-time accumulation as scheduling authority; existing evidence remains exact to its recorded configuration. Apply the [engine lifecycle and clock bounds](engine-contracts.md#clocks-histories-and-performance), [canonical f16 authority](gpu-f16-physics.md), P0-016/P0-024/P0-025/P0-026 and REQ-09/REQ-14 together. No threshold, workload or precision exception is introduced.

The user accepted the existing shared-clock synchronization evidence as sufficient to advance to Receiver on2026-10-03. Further exact mapping/feedback-age baselines, A diagnostic extensions and controlled100/250ms stalls are deferred; this is acceptance of the current synchronization behavior, not a newly measured timing Pass. Preserve the recorded limits and their later P0-034/P0-035 qualification gates; they do not create a new prerequisite to this next playable interaction.

## One authority and independently executing consumers

The Simulation host owns one session master clock, initialized once from its admitted monotonic native clock. Its nonzero session and clock generation identify the origin. It continues while the world is Building, Paused or Completed; it is not the committed physics tick and never restarts for Run or Reset.

Browser and Animation retain native clocks only as calibrated measurement/wakeup adapters to this master. They derive due work locally from the admitted master-time interval and immutable schedule; they do not wait for a Browser message on every pulse. Simulation clock/control service remains independent of awaiting a GPU dispatch. There is no additional clock worker or broadcast-per-pulse queue. A lost master/session faults or retires the session under the existing policy; no consumer elects a fallback authority.

Native origin mapping retains eight-probe qualification, current uncertainty/drift/expiry/recovery bounds and no shrinking retained uncertainty. Every mapped scheduling decision carries the matching session, clock generation and cadence revision. Animation maps to the same Simulation master; its mapping uncertainty must satisfy the existing end-to-end bound, not receive another additive allowance. The exact clock-control routes and their existing lease accounting must be specified in the forward codec before worker cutover.

## Exact pulses and bounded missed work

For admitted rate p/q Hz, pulse n has exact master-relative time n*q/p seconds. At integer master elapsed nanoseconds e, the due ordinal is floor(e*p/(1,000,000,000*q)), using checked widened integer products. Its first eligible integer timestamp is ceil(n*1,000,000,000*q/p). Calculate from the original epoch and ordinal, never by repeatedly adding a rounded period. A pulse exactly on its boundary is due; an earlier one is not. Non-divisor schedules such as 90 Hz animation with 120 Hz simulation and 144 Hz presentation require no common rounded period or giant least-common-multiple timer.

For a consumer whose mapped master time is an interval, use its lower bound to authorize a due pulse; retain the interval for freshness evidence. Timers and display callbacks only wake this calculation. Service return/ack/control traffic before bounded work. At most four whole simulation ticks run per turn. Every due physical tick is executed in order; no skipped tick, larger dt or discarded debt. More than 100 ms of physical-time debt still stops with Capacity.

Animation evaluates at most once per turn at its latest due ordinal, preserving reliable occurrences and their exact world identity. Superseded cosmetic evaluation opportunities may coalesce under that existing policy; they are reported, not presented as executed frames. Presentation applies at most once per actual display callback, choosing the latest eligible presentation ordinal. Missed opportunities never fabricate displayed frames. Lower device refresh than the selected target remains observable missed cadence and fails applicable performance admission, rather than changing the selected frequency silently.

## Active defaults and internal cadence configuration

The active Workshop uses Simulation 120 Hz, Animation 60 Hz and Presentation 60 Hz on the same master. These defaults live in one typed configuration owner and are not exposed as player controls. Preserve the internal settings/protocol and parameterized schedules so future development can change rates without another clock architecture. Rates and ordinals have distinct typed values; strings appear only at serialization/external boundaries. Internal capability and current defaults are:

| Setting | Admitted choices | Default |
| --- | --- | --- |
| Simulation commit cadence | 60, 120, 240 Hz | 120 Hz |
| Physical integration profile | Existing canonical 480 Hz f16 profile | 480 Hz |
| Animation evaluation cadence | 30, 60, 90, 120 Hz | 60 Hz |
| Presentation cadence | 30, 60, 90, 120, 144 Hz, or admitted display refresh | 60 Hz |

Alternate internal rates are future configuration capability, not active player options or a prerequisite to qualifying the current 120/60/60 defaults. Changing a default requires the affected numerical, timing, lifecycle and UI qualification; preserved alternate-rate evidence remains scoped to its exact inputs. Display refresh is an explicit admitted external rate captured in the schedule; subsequent refresh changes require re-admission and cannot create a second time authority. A fixed presentation selection remains fixed. Unsupported/undefined selectors, nonpositive rates, overflow and incompatible physical ratios reject atomically.

Simulation frequency changes real transactions and commits, not merely publication thinning. Each commit executes exactly 480/F physical substeps: eight at 60 Hz, four at 120 Hz, two at 240 Hz. The physical profile remains exact rational1/480 second. The generic force/contact path divides bounded ordinal/phase offsets by the admitted rate and reanchors its canonical primary state at fixed one-eighth-second boundaries; catalogue parts provide declarations to that shared path. Canonical stored velocity units remain unchanged. A substep ordinal is commitOrdinal*substepsPerCommit plus its local substep, with checked arithmetic and explicit profile identity. All GPU admission, contact/segment bounds, root iteration bounds and host validators consume that same value.

The current generic polynomial/contact implementation has no catalogue-specific law table. Prior numerical proof is reused only where unchanged inputs and arithmetic are independently established. New commit boundaries, up to eight stages per dispatch, terminal/contact handling, transaction cancellation and event counts still require affected numerical/GPU checks. No 60/240 Hz Pass is inferred from 120 Hz evidence. A different physical integration frequency is a separately declared numerical profile requiring its own Half dt, time/phase equations, operand/error bounds and qualification; this design does not fake that change by adjusting a timer.

The Run limit is 30 seconds of committed world time: 1,800/3,600/7,200 commits at the admitted rates. Replay/diagnostic storage must explicitly cover the admitted maximum, including the initial record (7,201 records for the current 128-byte state, 921,728 payload bytes and at most 57 chunks of 128 records). Recalculate actual state width and all metadata/managed/wire quotas after the forward ABI is fixed. Do not silently truncate or reuse the old 3,601-record cap. Reliable command tick identities stay exact; any tick-count capacity, lookahead or timeout is explicitly distinguished from physical duration before changing it.

## History capacity and unchanged ceilings

Retain seven complete samples in each of the three separate physical, world-animation and UI histories. The planning bound is ceil((16,666,667 ns delay + 2 * 1,000,000 ns mapping halfwidth) * 240 Hz / 1,000,000,000) + 2 = 7: a before endpoint, the intervening admitted pulse span, and an after endpoint. The former three-record ring cannot bracket this delay at 240 Hz. Seven is a fixed finite capacity, not permission to extrapolate or a guarantee for arbitrary bursts. Out-of-order, ambiguous, exhausted or missing brackets retain the prior complete world display; ordinary-load age still must pass at every admitted rate. In particular 60 Hz commits sit near one full publication interval of display delay and require actual bracket/age proof.

Keep history payload at most 192 KiB, retained metadata 32 KiB and scratch 32 KiB. World replacement peak is 7 * (max(Pold,Pnew) + max(Wold,Wnew) + U) + 1024 bytes; UI replacement is 7 * (Pnew + Wnew + max(Uold,Unew)) + 1024, with P/W/U the complete admitted sample sizes and all peak quotas validated before commit. For the current9,744-byte response including committed motion pieces, one physical history's declared reservation is7 * 9,744 +1,024 =69,232 bytes; this is payload/declared metadata accounting, not a managed-object-size measurement. The forward ABI must recompute from its actual new response width and separately enumerate mapped-entry, owner, prepared-candidate and copy scratch storage within the unchanged metadata/scratch ceilings. No new configuration is admitted from the old arithmetic.

## World time, autonomous UI and lifecycle

The world derives a running-time projection from the single master clock. Run establishes a world epoch and an admitted master-time start after its required recipient barrier, with tick zero at that start and the first whole tick due exactly 1/F later. This world lattice is epoch-relative; it never borrows an arbitrary next session pulse and advances a whole dt over a shorter first interval. Autonomous UI/animation and presentation schedules retain the session lattice. Committed world time is exactly n/F. Pause requires the exact session, world generation, cadence revision and projection, but permits a newer physical authority revision: queued ticks may commit before its arrival. It drains the owned in-flight tick, then freezes this world projection at the acknowledged committed endpoint. Resume and Step retain exact authority-revision admission in the paused world. Resume installs an acknowledged master-time anchor at the frozen committed n/F, with the next whole tick due exactly 1/F later, excluding paused elapsed time. Step advances exactly one configured simulation tick while paused, including its complete physical substeps, and completes only after the matching endpoint is displayed. It does not advance autonomous UI by an invented physics delta.

Autonomous UI and UI animation sample continuous master session time. World-dependent animation and physical presentation use the same selected committed world timestamp, with existing fixed display delay, coherent brackets and no extrapolation. They must not substitute an independently accumulated frame delta. Reset advances world generation, restores captured construction/configuration, retires old world histories and reseeds tick zero; it does not restart master time or reset an unrelated UI lifetime. Completed holds its matching endpoint while master-driven UI can continue. Visibility/suspension retains the existing acknowledged Pause/recalibration/reseed policy.

The Workshop exposes Pause, Resume, Step and Reset, but no frequency selectors or Apply-frequency action. Future cadence changes use the existing typed internal configuration boundary, not a parallel setting mechanism. Internal configuration installs only in acknowledged Building state. The host validates the full immutable settings, resources and profile, advances a nonreused cadence revision, and admits matching schedules in all required recipients before acknowledging application or allowing Run. Pending work/results from an older cadence revision cannot mutate the new schedule. Any precommit rejection leaves all old settings/schedules intact; postcommit recipient loss follows the existing Indeterminate/fault policy. Running, Paused and Completed reconfiguration rejects explicitly. No mid-Run frequency mutation, alias, migration or silent rebase is supported.

## Forward clock/configuration boundary

The first implementation uses these exact little-endian layouts. All enum values are declared in C# and emitted at the JS/WGSL boundary. Unknown versions, undefined values, nonzero reserved fields, stale identities, wrong routes and trailing/truncated bytes reject before mutation. No old-format decoder or implicit configuration default remains.

**Typed settings, 32 bytes.** Offsets: schema U32 at0 (version1); SimulationCadence U32 at4 (60/120/240 Hz map to1/2/3); PhysicalStepProfile U32 at8 (Canonical480Hz=1); AnimationCadence U32 at12 (30/60/90/120 map to1/2/3/4); PresentationCadence U32 at16 (AdmittedDisplay=0, fixed30/60/90/120/144 map to1..5); resolved presentation rate numerator U32 at20 and denominator U32 at24; reserved U32 at28. The resolved positive reduced rational must equal the fixed selection where fixed, or the separately admitted display rate where display-driven. Limit numerator<=240000, denominator<=10000 and30<=p/q<=240; validation uses integer products. Settings contain no game-value float or encoded behavior string.

**Master peer, 64 bytes; clock wire version3.** Version U32 at0, admitted native precision profile U32 at4, session128 at8, master clock generation U64 at24, master native origin I64 at32, requester native generation U64 at40, timestamp uncertainty U64 at48, requester role U32 at56, master role U32 at60 (Simulation only). Roles are Browser=1, Simulation=2, Animation=3. Origin and all native stamps are nonnegative. A probe appends sequence U64 at64 and requester native sent I64 at72 (80 bytes); reply appends master native received/sent I64 at80/88 (96 bytes). The master origin subtracts from mapped native time to yield typed master elapsed time. No browser epoch is authority. Existing probe/recovery bounds and exact identity checks apply independently to B→S and A→S; these are clock-control routes, not new animation gameplay command routes.

Clock diagnostic records become144 bytes: exact reply0..95, requester receipt I64 at96, outcome U32 at104, received length U32 at108, offset lower/upper I128 at112/128. The existing 128-entry clock ring remains bounded (18,432 payload bytes); collection capacities are recomputed from the declared run/cadence, not silently truncated.

**Reliable schedule control.** A64-byte header carries schema U32 at0 (version1), typed kind U32 at4 (Prepare=1, Prepared=2, Commit=3, Applied=4, Abort=5, Presented=6), session128 at8, master generation U64 at24, proposed cadence revision U64 at32, projection epoch U64 at40, sender/recipient role U32 at48/52, payload length U32 at56 and reserved U32 at60. Only S coordinates installation; B/A reply to S. Prepare has settings32, expected old cadence/projection U64 at32/40, typed transition U32 at48 (Configure=1, Run=2, Pause=3, Resume=4, Step=5, Completed=6, Reset=7), reserved U32 at52, target world generation U64 at56, target world tick U64 at64, endpoint publication identity U64 at72, and the complete prepared224-byte endpoint at80 (304-byte payload). Zero publication is permitted only for a nonpublication acknowledgement seed under its existing shape rule. Prepared/Applied/Presented carry final applied master-sample upper timestamp I64 and outcome/reason U32 at8/12 (16 bytes). An upper integer timestamp conservatively rounds the exact rational sample upward, so installation cannot rewind by fractional-nanosecond truncation. Abort carries reason U32 and reserved U32 (8 bytes).

Commit carries a144-byte schedule: settings0..31; cadence revision U64 at32; master generation U64 at40; master native origin I64 at48; install master elapsed I64 at56; first Animation/Presentation ordinal U64 at64/72; prior final Animation/Presentation master sample I64 at80/88; world generation U64 at96; projection anchor world tick U64 at104; projection anchor master elapsed I64 at112; typed world playback U32 at120; reserved U32 at124; projection epoch U64 at128; reserved U64 at136. World playback maps Building/Running/Paused/Completed/Faulted to0..4. Header/payload identities must agree.

World generation, projection epoch and cadence revision are distinct. Reset/Load retire the world generation. Run/Pause/Resume/Step/Completed transitions advance the projection epoch without treating an old endpoint capture as a new capture. The explicit projection anchor is not a physics capture stamp: retained tick-zero/paused endpoints preserve their original capture; history reseeds only at the matching admitted transition.

**Configuration transaction.** B sends a reliable ConfigureCadence request only in Building. S validates the full candidate, exact expected revision/profile and resource reservations; there is one pending installation. Prepare quiesces old cadence evaluations in B/A and reserves their new schedule/history state; input/acks remain serviceable. Recipients report their final applied master times. Rejection/timeout before commit aborts all prepared candidates and preserves the old configuration. Abort reopens each old schedule at its current due ordinal, never below its retained applied time; it does not replay skipped cosmetic opportunities. Published proposed revisions are never reused even after Abort. S then commits its prevalidated settings/world candidate, installs a fresh cadence revision and issues Commit. Recipients install exact matching state and reply Applied; only then is the settings command acknowledged Applied and Run enabled. A postcommit failure is Indeterminate/fault under the existing lifecycle contract, not rollback or automatic retry.

For each session-lattice consumer, firstOrdinal = floor(max(installMasterTime, priorFinalAppliedMasterTime)*p/(1e9*q))+1. No ordinal below this floor is eligible under the new revision; late delivery may evaluate the latest due ordinal only if it is at least firstOrdinal. This prevents a120→30 Hz change at50ms from replaying33.333ms after41.667ms. Run/Resume retain their separately declared epoch-relative first whole tick at anchor+1/F. A delayed commit never invents shortened physical dt.

**Bootstrap and owned clock route.** B creates one session and starts S and A with their exact role/build/schema identities. S admits its native clock and captures master origin once before issuing the authoritative bootstrap; generation starts at1. B transfers the two endpoints of one MessageChannel exactly once to S and A and retains neither endpoint. S owns one port, A owns the other; session disposal/crash closes both, retires the master generation and prevents old-port reuse. The route admits only typed Probe, Reply and ScheduleControl envelopes; S accepts A-origin probes and Prepared/Applied replies, A accepts S replies and Prepare/Commit/Abort. It does not accept animation gameplay requests, physical mutations or arbitrary callbacks. B↔S retains its existing owned worker channel. B and A each complete independent8-probe mapping qualification against S before initial schedule installation/Ready. Native clock profile or route failure rejects startup; there is no Browser-clock fallback.

**Projection transitions.** Every Workshop request also names its expected projection epoch; stale cadence/projection rejects before preparation. S serializes one lifecycle transition. Run prepares the existing tick-zero seed; Pause prevents new ticks and settles the current candidate before selecting its last committed endpoint; Resume prepares that unchanged paused endpoint; Step prepares exactly one GPU tick candidate while paused; Completed uses the already committed terminal endpoint; Reset prepares new-world tick-zero admission. Each Prepare identifies the candidate projection/endpoint without publishing it as current. Failed Step/Reset preparation discards its GPU candidate and preserves authority; failure cannot fabricate a capture stamp.

After all matching Prepared replies, S commits prevalidated world/projection assignments and publishes the matching schedule Commit before any new-projection read. B/A install their reserved seed/history and schedule together, acknowledge Applied, and reject old projection work. Reads/results remain bounded behind this lifecycle barrier; no arbitrary wait queue is added. Run/Resume anchors are chosen from the actual S master at commit, with the first tick due one full configured period later. Step remains Paused (or Completed); its command completion additionally waits for Browser Presented at the matching endpoint after actual property application, rather than treating history admission as rendering. Completed/Reset likewise retain their required endpoint application barrier. Postcommit recipient failure remains explicit Indeterminate/fault. If precommit Pause is rejected, its old running schedule retains real elapsed debt rather than silently excluding the preparation interval.

**Bounded reservations.** The coordinator owns one active schedule, one prepared schedule, one original lifecycle request, at most two recipient Prepared/Applied results, two reserved outbound controls, and one GPU precommit candidate owned by the existing device gate. B/A each own one active/prepared schedule, one prepared endpoint and one receipt/result. Fixed per-host schedule storage reservations are S4096 payload bytes/256 metadata bytes/1024 copy scratch and B/A2048 payload bytes/128 metadata bytes/1024 copy scratch each; these are sub-reservations within existing host/transport ceilings, not additional total budgets or managed-heap measurements. Arrays/records and result slots are fixed-size, with no installation queue or per-pulse task. The largest control is368 bytes (64+304), inside the1024-byte control lease limit. Native owner-layout/peak checks must account every actual field and retained copy within these reservations.

A Diagnostic trace has one1MiB raw-state reservation. Serialization uses one18432-byte raw chunk and24576 Base64 characters per full128-record chunk. Freeze a128KiB diagnostic output-scratch reservation for that raw chunk, its49152-byte UTF16 Base64 payload, and one bounded composed console payload plus headers. The encoder must avoid retaining simultaneous additional joined/copy strings outside that bound; direct chunk streaming and explicit lifetime checks are required. This scratch is distinct from state payload, counted in the Diagnostic host memory footprint, and absent from Production. No claim of complete managed occupancy follows from these payload ceilings.

## Forward replacement and acceptance

Before runtime edits, independently freeze exact configuration/pulse/clock message fields and versions, owner/commit ordering, bounded storage, and current call-site changes. Replace the private Run Stopwatch, hardcoded tick/120 conversions, tick*4 assumptions, local UI delta accumulation and independent animation scheduling; no old scheduling path remains reachable. Browser property application remains on the browser; animation evaluation belongs in the independent Animation worker. The current Animation project is a portable library, so its worker host/transport and the existing hint consumer cutover are actual work, not implied implementation.

Current proof qualifies the active120/60/60 defaults: integer/rational endpoint and overflow controls, atomic settings/old-revision rejection, actual two-worker Workshop without frequency controls, unchanged120Hz same-time physics/energy bounds, Pause/Step/Resume/Reset and UI activity while world time is paused, independent-worker progress, missed pulses/debt and delayed delivery, exact construction restoration and save/load where supported. Future changes to the internal configuration additionally require affected non-divisor/cross-rate and same-time profile checks before activation; compare simulation rates at equal physical times, not equal tick numbers. Existing alternate-rate evidence remains exact to its recorded inputs. Preserve the120Hz/four-step numerical baseline and report newly affected outcomes independently.

Production build, actual Chrome, resource limits and existing performance budgets remain required for each admitted configuration and applicable device. The fixed 120 Hz baseline still owns its prior deadline comparison; each selected cadence additionally reports its actual period/deadline misses without relaxing whole-tick CPU, age or presentation criteria. Synthetic 90/144 Hz scheduling is not actual display qualification. Required global audits, raw durability, complete occupancy/retention and publication remain open wherever existing proof is incomplete.
